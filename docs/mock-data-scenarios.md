# 목데이터와 개발용 시연

코드를 바꾸지 않았다. 버튼은 삭제·이름 변경 대상이 아니다. 필요 여부를 아직 판단할 수 없는 것은 유지로 둔다.

표시 조건: `BuildConfig.DEBUG`일 때 `screen_home.xml`의 개발용 영역. `MainScreens.bindFixtures`. 릴리스 레이아웃 분기는 `DevHomeGate`와 홈 바인딩을 따른다. 릴리스 APK에서 버튼이 숨는지는 이번 조사에서 빌드로 확인하지 않았다. 소스상 디버그 전용이다.

공통 안내 문자열: `home_dev_note`, `home_dev_graph_note`.

## 데이터가 남는 곳

| 종류 | id | 저장 | 재실행 |
| --- | --- | --- | --- |
| 예시 fixture | `fixture-` 봉투, `fixture-med-` 약 | `MedicationStore.rememberSample`. `exportState`에서 제외. `yakyeon_medications`에 없음 | 프로세스가 끝나면 사라짐 |
| 그래프 검증 | `env-`, `med-`, 병원명 `그래프 검증` | `commit` 후 `LocalMedicationState` | 남음. `예시 초기화`로 안 지워짐 |
| 개발용 그래프 관계 | 플래그만 | `MedicationStore.devGraphRelationScenario`. export 안 함 | 프로세스가 끝나면 꺼짐 |
| 직접 등록 | `env-`, `med-` | 로컬 prefs | 남음 |

홈의 복용 개수는 fixture를 포함한다. 그래프 노드(`DrugRelations.takingNodes`)는 `fixture-`, `dev-env-`, 샘플 표시 id를 뺀다. 그래프 검증 약은 샘플이 아니라서 노드가 된다.

`예시 초기화`는 fixture와 관계 플래그만 지운다. 그래프 검증 커밋과 직접 등록은 남는다. 다른 fixture를 고르면 `DevFixtures.apply`가 기존 fixture를 먼저 지운다. 그래프 검증 데이터는 그때도 남는다.

약통 연결 플래그는 fixture의 `SLOTS_PARTIAL`, `SLOTS_FULL`만 `markFixturePillbox`로 켠다. 그래프 검증 등록은 칸이 비어 있고 연결 플래그를 켜지 않는다.

## 겹침

- 예시 약과 그래프 검증 약은 홈 개수에 같이 더해질 수 있다. 그래프에는 검증 약만 나온다. 의도된 분리다. 하나로 합치지 않는다.
- `약통 일부`와 `약통 3칸`은 약통 탭용이다. 그래프 검증은 칸을 차지하지 않는다.
- 관계 버튼은 검증 버튼을 누를 때 꺼진다. 검증 후 다시 켜야 선이 생긴다.
- Figma 개발용 예시 프레임은 인벤토리의 47개 최상위에 없다. 위 버튼은 구현 쪽 시연 도구다.

## 시연할 때

1. 빈 그래프: 예시 초기화 후 그래프 검증 비우기. 샘플 노트와 빈 문구.
2. 노드만: 그래프 검증 약 3개. 선은 없음.
3. 선: 그 다음 개발용 그래프 관계 보기. 등재가 아니라고 배지를 같이 보여 준다.
4. 약통 카드: 약통 일부 사용 또는 3칸. 연결됨은 플래그다. Wi-Fi 연결 완료가 아니다.
5. 일정 색: 일정 상태 예시. 재실행하면 사라진다.
6. 직접 등록과 구분: 예시 초기화 뒤에도 그래프 검증 약과 최종 등록 약은 남는다.

실제 환자 데이터, 식약처 쌍, 기기 시리얼은 이 버튼들이 만들지 않는다.

## 2026-10-27 기준 처방 시나리오

앱에 넣는 경로와 단위 테스트가 같은 클래스 `com.example.yakyeon2.data.ScenarioPrescriptions`를 쓴다. 테스트 소스에 복사본을 두지 않는다. 앱 실행만으로 이 데이터가 들어가지 않는다. 디버그 홈의 `시나리오 한의원·내과`, `시나리오 피부과 추가`를 눌렀을 때만 `commit`한다. 같은 병원명이 있으면 다시 넣지 않는다. 작성 중인 등록(병원명, 약, 시각, 칸, 동의 체크, 예시 초안)이 있으면 넣지 않고 그 초안을 지우지 않는다. 빈 초안만 있을 때는 그 초안을 교체한다.

`예시 초기화`는 `fixture-`만 지운다. `시나리오 약 지우기`만 병원명이 한의원·내과·피부과인 봉투와 그 기록을 지운다. 그래프 검증 약과 직접 등록은 남는다. 시나리오 커밋은 `env-`/`med-`라 `yakyeon_medications`에 저장된다. 단위 테스트는 새 `MedicationStore`만 쓰므로 기기 prefs를 바꾸지 않는다.

용량은 표에 없다. 저장 조건이 용량을 요구하므로 모두 `TABLET_1`이다. 테스트용 값이다. 약5는 복용 시점 `AFTER_MEAL_30`와 `BEDTIME`을 함께 저장한다. 회차는 아침·점심·저녁·취침 네 개이고, 시점을 두 개 골랐다고 회차가 늘지 않는다. 병용금기 관계는 만들지 않는다. `pillboxConnected`는 켜지 않는다.

기존 개발용 버튼 10개, 시나리오 버튼 3개, `연결 재동의 연습`, 목록 예시, 약봉투 예시 행은 홈·목록·등록 화면에 두지 않는다. 디버그 빌드에서 로그인 `개발용 홈 보기`로 홈에 들어온 뒤, 인사말 `안녕하세요`를 길게 누르면 `개발용 도구` 화면이 열린다. 릴리스 빌드는 그 길게 누르기가 없다. 버튼이 하는 일은 이전과 같다. `예시 초기화`는 시나리오 커밋을 지우지 않고, `시나리오 약 지우기`는 그래프 검증 약과 직접 등록을 지우지 않는다.

| 봉투 | 병원 | 시각 | 기간 | 칸 | 등록 시각 |
| --- | --- | --- | --- | --- | --- |
| A | 한의원 | 09:00, 13:30, 20:00 | 2026-10-13~10-30, 양 끝 포함 | 인덱스 0, 화면 1번 | 시작일 00:00 |
| B | 내과 | 08:30, 14:00, 19:00, 취침 23:00 | 2026-10-17~10-31, 양 끝 포함 | 인덱스 1, 화면 2번 | 시작일 00:00 |
| C | 피부과 | 07:30, 12:30, 19:00 | 2026-10-27~11-02, 양 끝 포함 | 인덱스 2, 화면 3번 | 시작일 00:00. 처음에는 없음 |

약1~약3, 약7~약8은 아침·점심·저녁. 약4도 세 끼이고 시점은 식전. 약5는 네 회차. 약6은 아침·저녁. 약9는 저녁만.

칸 인덱스는 로컬 점유다. `pillboxConnected`는 켜지 않는다. Wi-Fi 연결이 아니다.

시작일 당일에 등록 시각보다 이른 회차는 `MedicationRules.includeScheduledRound`가 빼다. 시작일 00:00에 등록하면 그날 회차가 남는다. 2026-10-27 08:00에 피부과를 등록하면 그날 07:30 회차는 없고, 다음 날 아침은 있다. 이 동작은 단위 테스트가 확인했다.

2026-10-27 에뮬레이터에서 개발용 도구의 시나리오 버튼을 눌렀다. 한의원·내과 뒤 홈은 6개, 피부과 추가 뒤 9개였고 강제 종료 후에도 9개가 남았다. 그 다음 `그래프 검증 약 1개`를 눌러도 세 병원은 남고 그래프 검증이 추가됐다. `예시 초기화`는 그 봉투들을 지우지 않았다. `시나리오 약 지우기` 뒤에는 그래프 검증만 남았다. 그 확인 뒤 그래프 UI 테스트를 위해 앱 데이터를 지웠다.
