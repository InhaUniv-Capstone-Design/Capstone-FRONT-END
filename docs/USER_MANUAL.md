# 약연 사용자 매뉴얼

앱 버전 4.0, 패키지 이름 `com.gamcho.yakyeon`을 기준으로 썼습니다. 버튼 이름은 앱에 보이는 글자와 같습니다. 이 앱은 복약 기록을 돕는 도구이며 의료행위나 복약지도가 아닙니다.

화면 그림이 들어갈 자리는 아래처럼 비워 두었습니다.

> 화면 캡처: (파일 이름). 캡션: (화면에 보여야 할 것).

## PART 1. 약연 시작하기

### 1. 약연 서비스 소개

약연은 약 정보를 등록하고, 오늘 먹을 약을 확인하고, 스마트 약통 칸에 약봉투를 배정하는 Android 앱입니다. 로그인하면 약, 일정, 약통 상태는 서버에서 불러옵니다.

아래쪽 탭은 다섯 개입니다.

| 탭 | 하는 일 |
| --- | --- |
| 홈 | 오늘 복용, 아직 체크하지 않은 약, 병용금기 등재 건수 |
| 복약 일정 | 날짜를 골라 그날의 복용 일정 확인 |
| 그래프 | 함께 먹는 약의 병용금기 등재 여부 |
| 약통 | 연결된 약통, 칸 상태, 기기 등록 |
| 설정 | 계정, 알림, 연동, 약관 |

약 목록은 홈이 아니라 약물 등록 흐름의 **내 약물** 화면입니다. 들어가는 버튼은 홈 쪽 약물 입구입니다. 정확한 아이콘 위치는 아래 캡처로 확인합니다.

> 화면 캡처: `home-tabs.png`. 캡션: 아래 탭 다섯 개와 약물 목록으로 가는 버튼.

### 2. 앱 설치 및 APK 실행

1. 저장소의 `dist/Yakyeon_Test_v4.0.apk`를 휴대폰으로 받습니다.
2. 내 파일 앱에서 APK를 누릅니다.
3. 설치가 막히면 **이 출처 허용**을 켠 뒤 다시 설치합니다.
4. 앱 서랍에서 **yakyeon2**를 엽니다.

필요한 Android는 8.0 이상입니다. 3.0이 깔려 있으면 지우지 말고 위에 덮어씁니다. 서명이 다른 같은 이름 앱이 있으면 먼저 제거한 뒤 설치합니다. 컴퓨터에서는 `adb install -r dist/Yakyeon_Test_v4.0.apk`를 씁니다.

이 APK의 서버 주소는 배포 서버입니다. 휴대폰의 localhost를 보지 않습니다.

### 3. 최초 실행 시 필요한 권한

처음 실행하면 알림 권한을 묻습니다. 복약 알림을 받으려면 허용합니다. 거부해도 로그인 화면은 열립니다. 나중에 켜려면 휴대폰 **설정 > 앱 > yakyeon2 > 알림**에서 허용합니다.

약봉투를 찍으려면 카메라 권한이 필요합니다. 카메라가 열리지 않으면 **사진 촬영** 대신 **갤러리에서 선택**을 씁니다.

### 4. 회원가입

1. 로그인 화면에서 **회원가입**을 누릅니다.
2. **누구의 약을 관리하시나요?**에서 **본인** 또는 **대리인**을 고르고 **다음**을 누릅니다.
3. 이름, 생년월일, 휴대폰 번호, 아이디, 비밀번호를 입력합니다. `*`가 있는 항목은 필수입니다.
4. 아이디는 **중복 확인**을 합니다. “사용할 수 있는 아이디입니다.”가 나와야 합니다.
5. 휴대폰 인증을 끝낸 뒤 가입을 완료합니다. “가입되었습니다. 로그인해 주세요.”가 나오면 로그인 화면으로 돌아갑니다.

| 항목 | 입력 방법 | 필수 | 주의 |
| --- | --- | --- | --- |
| 가입 유형 | 본인 또는 대리인 | 예 | 고르지 않으면 “전부 입력해 주세요” |
| 이름 | 글자 입력 | 예 | |
| 생년월일 | `YYYY.MM.DD`로 선택 | 예 | 잘못되면 “생년월일을 다시 선택해 주세요.” |
| 휴대폰번호 | 숫자만 | 예 | 010으로 시작하는 11자리 |
| 아이디 | 6~20자 영문, 숫자 | 예 | 중복 확인 필요 |
| 비밀번호 | 직접 입력 | 예 | 영문, 숫자, 특수문자 포함 8~64자 |

> 화면 캡처: `signup-type.png`, `signup-form.png`. 캡션: 본인/대리인 선택과 필수 표시 `*`.

### 5. 휴대폰 인증

서버가 어떤 인증 방식을 주는지에 따라 화면이 둘 중 하나로 열립니다. 어느 방식이 현재 서버의 기본인지는 **개발팀 확인 필요**입니다. 화면에 나온 안내만 따릅니다.

**인증번호를 앱에 입력하는 경우**

1. **인증번호 받기**를 누릅니다. “인증번호를 보냈습니다.”를 확인합니다.
2. 문자로 온 숫자 6자리를 입력합니다.
3. “인증이 완료되었습니다”가 나온 뒤에만 다음으로 갑니다.

**앱이 보여 준 코드를 문자로 보내는 경우**

1. 화면에 큰 숫자 코드와 받을 번호가 나옵니다.
2. **문자 앱으로 보내기**를 누릅니다. 코드만 보내고 다른 글자나 공백을 붙이지 않습니다.
3. 문자를 보낸 뒤 앱으로 돌아와 확인을 누릅니다. “문자가 아직 확인되지 않았어요”이면 조금 기다렸다가 다시 누릅니다.
4. 이 휴대폰에서 문자를 보낼 수 없으면 다른 휴대폰으로 그 번호에 코드만 보냅니다.

공통 주의:

- 번호를 바꾸면 인증을 다시 합니다.
- “인증 시간이 만료되었습니다” 또는 “인증이 만료되었거나 유효하지 않습니다”가 나오면 처음부터 다시 요청합니다.
- “요청이 너무 많습니다”이면 잠시 쉬었다가 다시 합니다.

### 6. 로그인 및 로그아웃

**로그인**

1. 아이디와 비밀번호를 입력합니다.
2. **로그인**을 누릅니다.
3. 아래 탭이 보이면 로그인된 것입니다.

로그인 화면의 작은 글은 시작하면 이용약관과 개인정보 처리방침에 동의한다는 안내입니다.

**로그아웃**

1. **설정** 탭을 엽니다.
2. **프로필 및 계정관리**로 들어갑니다.
3. **로그아웃**을 누르고 “로그아웃 하시겠습니까?”에서 확인합니다.
4. 로그인 화면으로 돌아오면 끝난 것입니다.

### 7. 아이디 찾기 및 비밀번호 재설정

로그인 화면의 **아이디 찾기**, **비밀번호 재설정**은 서버에 요청합니다.

**아이디 찾기**

1. **아이디 찾기**를 누릅니다.
2. 가입할 때 쓴 이름과 휴대폰 번호를 입력하고 휴대폰 인증을 끝냅니다.
3. 계정이 있으면 복약자 계정 또는 보호자 계정으로 아이디가 나옵니다.
4. 없으면 “입력하신 정보와 일치하는 계정이 없습니다.”가 나옵니다.
5. **로그인 화면으로 이동**으로 돌아갑니다.

**비밀번호 재설정**

1. **비밀번호 재설정**을 누릅니다.
2. 아이디와 휴대폰 번호를 입력하고 문자 인증을 끝냅니다.
3. 새 비밀번호와 확인을 입력합니다. 규칙은 가입과 같습니다.
4. “비밀번호가 성공적으로 변경되었습니다. 새로운 비밀번호로 로그인해 주세요.”가 나오면 그 비밀번호로 로그인합니다.

두 비밀번호가 다르면 “새 비밀번호가 일치하지 않습니다.”가 나옵니다. 인증이 끝나기 전에 번호를 바꾸면 “휴대폰 인증을 완료해 주세요.” 또는 처음부터 다시 하라는 안내가 나옵니다.

로그인한 뒤 비밀번호를 바꾸는 곳은 다릅니다. **설정 > 프로필 및 계정관리 > 비밀번호 변경**에서 현재 비밀번호와 새 비밀번호를 입력합니다. 바뀌면 다시 로그인합니다.

### 8. 전체 화면 구성

로그인 후 이동은 아래 탭과 약물 목록입니다.

1. **홈**: 오늘 상태와 **드셨나요?**
2. **복약 일정**: 날짜별 일정
3. **그래프**: 병용금기 등재
4. **약통**: 기기와 칸
5. **설정**: 계정, 알림, 연동, 약관
6. **내 약물**: 등록한 약봉투. 여기서 **추가 등록**, 시간 수정, 칸 변경, 종료를 합니다.

> 화면 캡처: `tabs.png`. 캡션: 다섯 탭의 실제 아이콘.

## PART 2. 약물 등록하기

약을 서버에 남기려면 로그인되어 있어야 합니다. 로그인하지 않으면 서버 약을 불러오지 않습니다.

### 1. 등록 화면으로 들어가기

1. **내 약물**을 엽니다.
2. 처음이면 약 등록 동의 안내가 나옵니다.
3. “(필수) 복약정보 수집·이용에 동의합니다.”와 “(필수) 서비스 이용 고지를 확인했습니다.”를 체크합니다.
4. **동의하고 약 등록**을 누릅니다.
5. 약봉투 화면에서 **추가 등록** 또는 사진 등록으로 약을 넣습니다.

동의 버전을 서버에서 찾지 못하면 “약 등록 동의 버전을 서버 약관에서 찾지 못했습니다”가 나오고 등록은 시작되지 않습니다. 이때 동의를 건너뛰지 않습니다.

촬영 전에 처방전의 주민등록번호는 가립니다. 본인 약만 등록합니다.

### 2. 약봉투 사진과 OCR

1. **촬영하기** 또는 **사진 등록**에서 **사진 촬영**이나 **갤러리에서 선택**을 누릅니다.
2. 약 이름과 용량이 잘 보이게 찍습니다.
3. 인식이 끝나면 약이 초안으로 채워집니다.
4. “인식된 약이 없습니다. 직접 입력해 주세요.”이면 아래 수동 등록으로 갑니다.
5. “서버가 돌려준 인식 초안입니다. 실제 판독 서비스 결과가 아니면 내용을 확인한 뒤 등록해 주세요.”가 있으면 숫자와 이름을 약봉투와 비교합니다. OCR은 틀릴 수 있습니다.

용량, 횟수, 일수가 비어도 약 이름이 있으면 초안은 남습니다. 비어 있는 값을 앱이 0이나 1로 채우지 않습니다. 시간대가 없고 하루 횟수만 있으면 횟수에 맞춰 아침, 점심, 저녁, 취침이 초안으로 체크될 수 있습니다. 서버가 시간대를 주면 그 값을 씁니다. 저장 전에 반드시 고칩니다.

### 3. OCR 결과 수정

각 약 줄을 열어 이름, 용량, 기간, 횟수, 시점을 약봉투와 같게 고칩니다. 맞는 약만 **확인 완료**를 체크합니다. 틀린 줄은 고치기 전에는 체크하지 않습니다.

### 4. 수동 등록

1. **추가 등록**으로 약 줄을 만듭니다.
2. 병원명을 적습니다. 비어 있으면 최종 등록이 되지 않습니다.
3. 약마다 아래 표를 채웁니다.
4. 약마다 **확인 완료**를 체크합니다.
5. 약통에 넣을 거면 **약통에 넣기**, 칸 없이 등록하려면 **약통 없이 사용하기**를 누릅니다.
6. 시간 창에서 시각을 확인하고 최종 등록을 누릅니다.

### 5와 6. 입력 항목

| 항목 | 입력 방법 | 필수 여부 | 주의사항 |
| --- | --- | --- | --- |
| 병원명 | 글자 입력. 화면 문구는 “병원 이름을 적어주세요” | 필수 | 비어 있으면 “필수 항목을 입력해주세요” |
| 약국명 | 있으면 입력 | 선택 | 비어 있어도 등록은 진행됩니다 |
| 약물명 | 검색하거나 직접 입력. 최대 500자 | 필수 | 약봉투의 이름과 비교합니다 |
| 용량 | 정은 0.5·1·2·3, 캡슐은 1·2. 포, mL, g도 그 수량만 | 필수 | 0은 저장되지 않습니다. 다른 수량은 “정은 0.5·1·2·3…” 안내가 납니다 |
| 복용 횟수 | **아침**, **점심**, **저녁**, **취침** 체크. 필요하면 **필요 시** | 필수 | 필요 시가 아니면 회차를 하나 이상 고릅니다. 필요 시는 아침·점심·저녁·취침과 같이 쓰지 않습니다 |
| 복용 시점 | 아침·점심·저녁이 있으면 **식전**, **식후**, **식사와 함께** 중 정확히 하나 | 그 경우 필수 | 두 개를 고르거나 하나도 없으면 확인 완료가 되지 않습니다. 취침만 있으면 식전·식후·함께는 고르지 않습니다. **상시**는 필요 시와 연결됩니다 |
| 복용 시작일 | 날짜 선택 | 필수 | 종료일보다 늦으면 안 됩니다 |
| 복용 종료일 | 날짜 선택 | 필수 | 시작일 포함 1일 이상 365일 이하 |
| 확인 완료 | 약마다 체크 | 필수 | 체크되지 않으면 “확인완료에 체크해주세요” |
| 복용 시각 | 아침·점심·저녁·취침 중 고른 회차만, 약봉투마다 시각 한 벌 | 필수 | 사용자가 고른 시각 그대로 저장됩니다. 식전·식후로 30분을 더하거나 빼지 않습니다 |
| 약통 칸 | **약통에 넣기** 후 빈 칸 선택 | 약통을 쓸 때만 | **약통 없이 사용하기**면 칸 없이 등록합니다 |

처방일은 따로 적지 않으면 약들의 시작일 중 가장 이른 날로 서버에 넘어갑니다. 이것은 처방전에서 읽은 날짜가 아닙니다.

### 7과 8. 횟수와 시점

1. 먹는 회차만 켭니다. 예: 아침과 저녁만 먹으면 그 둘만 켭니다.
2. 아침, 점심, 저녁 중 하나라도 켜면 시점은 **식전**, **식후**, **식사와 함께** 중 하나만 고릅니다.
3. 취침만 먹으면 취침만 켜고 식전·식후·함께는 끄지 않은 상태가 아니라, 그 세 개를 고르지 않습니다.
4. 아플 때만 먹는 약이면 **필요 시**를 켭니다. 이때 상시가 같이 맞는 상태입니다. 필요 시에는 아침·점심·저녁·취침을 같이 켜지 않습니다.

한 약봉투의 아침 시각은 그 봉투 안 약들이 같이 씁니다. 약마다 아침 시각을 다르게 둘 수는 없습니다.

### 9와 10. 날짜

1. 시작일과 종료일을 달력에서 고릅니다.
2. 종료일이 시작일보다 이르면 저장되지 않습니다.
3. 기간은 시작일 포함 365일을 넘기면 안 됩니다.
4. 지난 날짜를 시작일로 고를 수 있는지는 달력이 허용하는 범위입니다. 막히면 그 날짜를 바꾸기만 하고, 다른 약을 다시 만들지는 않습니다.

### 11. 저장

1. 모든 약의 **확인 완료**를 체크합니다.
2. 약통을 쓰면 **약통에 넣기**로 빈 칸을 고르고 완료합니다. 칸 없이 쓰려면 **약통 없이 사용하기**를 누릅니다.
3. 시간 창에서 고른 회차의 시각을 확인합니다. 위·아래 화살표로 바꿉니다.
4. 최종 등록을 누릅니다.
5. **내 약물** 목록이 열리고, 방금 등록한 약봉투가 맨 위에 보이면 저장된 것입니다.

시간 규칙에 걸리면 창 제목 “복용 시간이 올바르지 않습니다.”와 함께 다음 두 줄이 나옵니다.

- 복용 시간을 전부 입력해야해요.
- 최소 4시간 이상 간격으로 복용해야해요

화면 아래나 짧은 안내에는 이 문장이 따로 나옵니다. “아침, 점심, 저녁, 취침 순서로 시각을 설정해주세요. 시간대 사이는 최소 4시간입니다. 아침·점심·저녁은 20:59까지, 취침은 23:59까지 설정할 수 있습니다.”

“필수 항목을 입력해주세요”는 병원명, 약 이름, 용량, 날짜, 회차, 확인 완료 중 하나가 비었다는 뜻입니다. 어느 칸인지는 문장만으로는 나오지 않으므로 표를 위에서부터 다시 봅니다. 1초 정도만 보이는 짧은 안내일 수 있으니 화면을 바로 넘기지 않습니다.

### 12. 등록한 약 확인과 수정

**내 약물**에서 약봉투를 봅니다.

- **복용 시간 수정**: 그 봉투의 아침·점심·저녁·취침 시각만 바꿉니다. 이름과 용량은 이 버튼으로 바뀌지 않습니다.
- 약을 먹지 않는 회차의 시각을 저장해도 그 회차의 복용 기록은 생기지 않습니다.

이미 저장된 약의 이름, 용량, 기간을 다시 고치는 화면은 코드에서 확인하지 못했습니다. **개발팀 확인 필요.** 틀렸다면 그 약을 함부로 또 등록하지 말고, 아래 종료 또는 삭제 안내를 읽은 뒤 개발팀에 묻습니다.

### 13. 삭제와 종료

복용 중인 약봉투에서 할 수 있는 일은 세 가지입니다.

| 동작 | 방법 | 결과 |
| --- | --- | --- |
| 약 하나 종료 | 약 줄을 짧게 누름 | “약 복용 종료”. 지난 기록은 남음 |
| 약 하나 삭제 | 약 줄을 길게 누름 | “이 약을 목록에서 삭제할까요? 지난 복용 기록은 남습니다.” |
| 봉투 전체 종료 | **복용 조기 종료하기** | “종료한 약물은 복용 종료 목록에서 확인할 수 있어요.” |

삭제는 되돌리기 어렵습니다. 확인 창의 문구를 읽기 전에는 **삭제**나 **종료**를 누르지 않습니다.

### 14. OCR이 틀릴 때

1. 저장하지 않습니다. **확인 완료**를 끄거나 체크하기 전에 고칩니다.
2. 이름, 용량, 횟수, 기간을 약봉투와 같게 직접 고칩니다.
3. 인식된 약이 없으면 수동으로 줄을 추가합니다.
4. 이미 저장한 뒤에 알았다면 새 봉투를 또 만들기 전에, 방금 만든 봉투를 목록에서 찾아 종료할지 개발팀에 보일지 정합니다.

## PART 3. 등록한 약물 관리

### 1. 목록

**내 약물**에 복용 중인 약봉투가 위에, 끝난 약봉투가 **복용 종료한 약물** 쪽에 나옵니다. 새로 등록한 봉투가 맨 위입니다.

### 2. 상세

봉투 카드에 병원 이름, 약 개수, 배정된 칸 번호, 각 약의 이름과 횟수가 나옵니다. 별도의 “상세 보기” 버튼 이름은 코드에서 확인하지 못했습니다.

### 3. 수정

등록이 끝난 뒤에는 **복용 시간 수정**과 약통 **칸 변경**만 확인했습니다. 이름과 용량 수정은 **개발팀 확인 필요**입니다.

### 4. 삭제

PART 2의 표를 따릅니다. 앱을 지워도 서버의 약이 지워진다고 생각하지 않습니다. 계정 삭제는 설정에서만, 안내를 읽은 뒤에 합니다.

### 5와 6. 복용 중과 종료

**복용 조기 종료하기**를 하거나 약 줄을 눌러 종료하면 **복용 종료**로 표시되고 시간 수정과 칸 변경 버튼이 사라집니다. 종료일이 지나 서버가 끝난 약으로 주면 같은 종료 표시가 됩니다. 끝난 약을 앱이 자동으로 지운다는 동작은 확인하지 못했습니다.

### 7. 약봉투와 앱이 다를 때

목록의 이름, 용량, 횟수를 약봉투와 한 줄씩 비교합니다. 다르면 그 약을 또 등록하지 않고, 종료와 삭제 중 어떤 것이 맞는지 개발팀에 약 이름을 알려 확인합니다.

## PART 4. 스마트 약통

약통은 3칸입니다. 앱의 1번 칸은 기기의 1번 칸과 같게 쓰도록 만들어져 있습니다. 기기 LCD의 `BOX3 TAKEN` 같은 글자는 앱이 그리는 문장이 아니라 약통이 보여 주는 문장입니다. LCD에 나왔다고 앱 기록이 바뀐 것은 아닙니다.

### 1. 칸의 의미

| 표시 | 의미 |
| --- | --- |
| 비어 있음 | 새 약봉투를 넣을 수 있음 |
| 사용 중, 자물쇠 | 이미 약이 있음. 새 봉투로는 선택 불가 |
| 충전 대기 | 칸은 배정됐으나 약을 넣는 상태가 아님 |
| 정상 | 서버가 정상으로 준 상태 |
| 약통이 열렸습니다 | 열림이 보고된 상태 |

### 2부터 5. 약통 등록

1. **약통** 탭을 엽니다.
2. 연결된 약통이 없으면 **기기 찾기**로 들어갑니다.
3. **약통 라벨의 시리얼번호**와 **약통 라벨의 비밀값**을 라벨과 같게 입력합니다.
4. 등록을 실행합니다.
5. 약통 탭에 시리얼과 **연결 상태**가 보이면 등록된 것입니다. “연결된 약통이 없어요”이면 아직 아닙니다.

비밀값은 채팅이나 문서에 옮겨 적지 않습니다. 등록이 실패하면 라벨을 다시 보고, 숫자를 한 글자씩 비교합니다. 앱 데이터를 지우지는 않습니다.

약통 연결은 안내 문구대로 와이파이를 사용합니다. 휴대폰 모바일 데이터만으로는 약통 자체가 서버에 붙지 않을 수 있습니다. 약통이 서버에 붙는 와이파이 설정 순서는 이 앱 화면만으로는 확인하지 못했습니다. **개발팀 확인 필요.**

### 6. 상태 확인

약통 탭에서 **연결 상태**가 **연결됨** 또는 **오프라인**으로 보이고, 칸 사용 수와 각 칸의 병원 이름이 나옵니다. **기기 동기화** 줄에는 서버가 준 값에 따라 “기기가 현재 일정을 받았습니다.”, “기기가 다음에 연결될 때 반영돼요.”, “최근 동기화 시각 없음” 중 하나가 나옵니다. 그 줄을 누르면 동기화를 요청합니다. 접수가 되면 “서버에 동기화를 접수했습니다. 기기가 받았는지는 이 응답으로 확인되지 않습니다.”가 나옵니다. 이 문장만으로 약통 화면이 바뀌었다고 보지 않습니다.

**부저 알람**과 **LED 알람** 스위치는 서버에 `buzzer_enabled`, `led_enabled`로 저장됩니다. 스위치가 켜져도 약통 앞면의 소리가 즉시 나는지는 기기가 서버 값을 받은 뒤에야 알 수 있습니다. 앱 스위치와 기기 소리가 다르면 기기를 초기화하지 말고 동기화 시각을 확인합니다.

### 7. 칸 배정

**새 약봉투를 등록하면서**

1. **약통에 넣기**를 누릅니다.
2. 약통이 없으면 “연결된 약통이 없어” 배정하지 않습니다. 먼저 기기를 등록합니다.
3. 비어 있는 칸만 고릅니다. 이미 약이 있는 칸은 자물쇠와 “사용 중인 칸은 선택할 수 없습니다.”로 막혀 있습니다.
4. 약을 칸에 넣은 뒤 그 칸을 고르는 것이 맞습니다. 넣기 전에 칸만 고르면 기록과 실제 칸이 어긋날 수 있다는 안내가 있습니다.

**이미 등록된 약**

1. **내 약물**에서 그 봉투의 칸 변경을 누릅니다.
2. 비어 있는 칸이나 이 약이 이미 쓰는 칸만 고릅니다.
3. 저장하면 “약통 칸을 배정했습니다.”가 나옵니다.

### 8과 9. 해제와 변경

칸을 비울 때는 약통 화면의 **칸 비우기**를 사용합니다. 확인 창 제목은 “이 칸을 비우시겠습니까?”이고, 본문은 “이 칸에 배정된 약물의 약통 배정을 해제합니다.”입니다. 확인 버튼 글자는 **삭제**이지만, 이 동작은 칸 배정만 해제합니다. 약 자체와 지난 복용 기록을 서버에서 지우는 버튼이 아닙니다. 끝난 뒤에는 “약통 칸의 배정이 해제되었어요.”가 나옵니다. 다른 칸으로 바꾸려면 칸 변경에서 빈 칸을 고릅니다. 사용 중인 칸을 억지로 고르지 않습니다.

연결 해제는 약통 설정의 **연결 해제**입니다. “서버에 약통 등록 해제를 요청합니다. 이 기기의 복약 기록은 지우지 않습니다.” 기록까지 지우고 싶을 때 쓰는 버튼이 아닙니다.

### 10. 충전

서버 상태가 **충전 대기**이면 그 칸에 약을 채워야 하는 상태입니다. 앱에 별도의 “충전 완료” 버튼이 있는지는 약통 탭의 칸 카드에 그 글자가 있을 때만 누릅니다. 없으면 **개발팀 확인 필요**이며, 칸을 비웠다 다시 배정하는 방식으로 우회하지 않습니다.

### 11과 12. 연결 실패

1. 시리얼과 비밀값을 라벨과 다시 비교합니다.
2. 휴대폰은 인터넷이 되는지 봅니다. “서버에 연결할 수 없습니다”이면 앱이 서버에 닿지 못한 것입니다.
3. 약통 전원이 켜져 있는지, 약통 화면의 연결 상태가 연결 안 됨인지 봅니다.
4. 같은 기기를 한 번 더 등록하기 전에 이미 “연결됨”인지 확인합니다. 중복 등록은 하지 않습니다.

## PART 5. 복용 관리

### 1. 홈

홈은 오늘 복용입니다. 먹을 시각이 지난 약이 있으면 “아직 복용을 체크하지 않은 약이 있어요”와 **드셨나요?**가 보입니다. 앞으로 먹을 약은 그 아래 예정으로 보입니다. 오늘 일정이 없으면 비어 있다는 안내가 나옵니다. 오늘 분이 모두 끝나면 완료 표시로 바뀝니다.

병용금기 문장은 “병용금기 등재 정보가 N건 있어요”만 나옵니다. 등재가 0건이어도 안전하다는 뜻은 아닙니다. 자세한 관계는 **그래프** 탭에서 봅니다.

### 2. 예정 일정

**복약 일정** 탭에서 날짜를 바꿉니다. 그날 서버가 준 회차와 상태가 목록으로 나옵니다.

### 3. 복용 체크

1. 홈에서 **드셨나요?**를 누릅니다.
2. 누락된 약이 하나여도 목록이 먼저 열립니다. 제목은 “아직 복용을 체크하지 않은 약이 있어요”, 안내는 “드셨나요?”입니다.
3. 먹은 약 한 줄을 누릅니다.
4. “몇시에 드셨나요?” 위에 병원 이름과 약 이름이 나옵니다.
5. 시각은 지금 시각에서 시작합니다. 미래 시각은 선택되지 않습니다. **수동으로 기록하기**로 저장합니다.
6. 아직 남은 약이 있으면 목록으로 돌아갑니다. 다음 약의 시각 창이 자동으로 열리지는 않습니다.

오늘 기록만 입력·수정할 수 있습니다. 지난 날짜는 읽기 전용입니다. “3시간이 지나 선택할 수 없습니다.”가 나오면 그 회차는 앱에서 시각을 고칠 수 없습니다.

약통 버튼을 눌러 기기가 복용을 알리면, 앱은 알림을 받은 뒤 서버에서 오늘 복용을 다시 읽어 화면을 바꿉니다. 기기 화면에 `TAKEN`이 보여도, 앱 홈이 바뀌기 전에는 앱 기록이 갱신된 것이 아닙니다.

### 4와 5. 안 먹은 약, 시간이 지난 약

체크하지 않았고 서버가 아직 확인할 수 있는 구간이면 홈에 누락으로 남습니다. 일정 화면의 상태 글자는 서버가 준 값입니다. 정시, 지연, 누락 같은 구분이 목록에 보일 수 있습니다. 지연으로 보일 정확한 분 수는 서버가 정합니다. **개발팀 확인 필요:** 앱은 그 상태를 보여 주고, 지연 기준 분을 앱이 따로 계산해 덮어쓰지는 않습니다.

### 6. 복용 완료 후

저장되면 “복용 기록이 저장되었습니다.”가 나올 수 있습니다. 홈을 다시 그릴 때 그 약은 예정이나 누락 목록에서 빠지고, 오늘 분이 모두 끝나면 완료 영역이 보입니다.

### 7. 그래프

**그래프** 탭의 설명은 “함께 복용 중인 약의 병용금기 등재 여부만 표시합니다.”입니다. 복용 중인 약이 없으면 “현재 복용 중인 약이 없습니다.”입니다. 점을 누르면 그 약의 등재 설명이 나옵니다. 검사를 마치지 못한 약을 누르면 “이 약은 병용금기 검사를 마치지 못했습니다.”가 나올 수 있습니다. 등재된 관계가 없다는 문장이 있으면, 그것이 모든 약이 안전하다는 뜻은 아닙니다.

### 8. 날짜별 기록

날짜를 골라 보는 화면은 **복약 일정** 탭입니다. 홈이나 약물 목록 위쪽의 달력 아이콘도 이 화면을 엽니다. 아래 탭에 “캘린더”라는 이름은 없습니다.

복용 내역 화면용 코드는 있으나, 탭이나 버튼에서 그 화면을 여는 연결은 확인하지 못했습니다. **개발팀 확인 필요.** 기간을 직접 고르는 조회는 최대 90일입니다. 넘기면 “조회 기간은 최대 90일입니다.”가 나옵니다.

### 9. 기록이 다를 때

1. 홈을 연 시각과 약통에서 버튼을 누른 시각을 적습니다.
2. 앱을 종료하지 말고 **복약 일정**에서 같은 날짜를 다시 엽니다.
3. 약통 LCD 문장과 앱 목록이 다르면, 둘 다 스크린샷으로 남기고 약을 다시 등록하지 않습니다.
4. 방금 앱에서 다른 저장을 끝낸 직후 몇 초는 약통 복용 알림이 화면을 바로 다시 읽지 않을 수 있습니다. 잠시 후 홈을 다시 엽니다.

## PART 6. 알림 및 설정

### 1. 복용 알림

**설정 > 알림 설정**의 스위치는 서버에 저장됩니다. 화면의 도움말은 다음과 같습니다.

| 스위치 | 화면에 적힌 조건 |
| --- | --- |
| 복용 시간 알림 | 복용 10분 전에 알려드려요 |
| 미복용 알림 | 예정 시간 30분 후 다시 알려드려요 |
| 복용 종료 예정 알림 | 종료 3일 전에 알려드려요 |
| 약통 상태 알림 | 복용 확인, 기기 이상. 끄면 하위 항목은 바뀌지 않음 |
| 복용 알림 | 복용 버튼을 누르면 |
| 미복용 알림(약통) | 1시간이 지나도 복약이 감지되지 않으면 |
| 기기 이상 감지 | 연결 불안정 등 |

이 문장이 서버의 실제 발송 시각과 같은지는 **개발팀 확인 필요**입니다. 앱은 스위치를 저장하고, 알림 문장을 서버가 보내면 보여 줍니다. 앱이 자체로 10분 전 알람을 예약하는 화면은 없습니다.

약통이 복용을 알리면 앱은 그 푸시를 받은 뒤 오늘 복용을 다시 읽습니다. 이미 먹은 일정이라고 서버가 표시한 미복용 알림은 다시 띄우지 않습니다. 약통이 열렸다는 알림은 띄우지 않습니다. 센서가 약 투입만 감지하면 알림 없이 약통 화면을 다시 불러옵니다.

### 2와 3. 권한이 꺼져 있거나 알림이 없을 때

설정 화면에 “기기의 알림 권한이 꺼져 있으면 알림을 받을 수 없어요.”가 있으면 휴대폰 설정에서 yakyeon2 알림을 켭니다. 권한을 켜도 서버가 알림을 보내지 않으면 앱에는 아무것도 오지 않습니다. 앱을 지우고 다시 설치하지 않습니다. 시각, 켠 스위치 이름, 권한 상태를 적어 개발팀에 보냅니다.

### 4. 설정에 있는 메뉴

| 메뉴 | 확인된 동작 |
| --- | --- |
| 프로필 및 계정관리 | 이름, 생년월일, 휴대폰 표시. 이름 수정. 비밀번호 변경. 로그아웃. 회원 탈퇴 |
| 복약자 연동 관리 | 연동된 복약자 또는 보호자 목록. 연동 해제 |
| 알림 설정 | 위 스위치. 서버에 저장 |
| 복약 이력 공유 | 최근 7일, 30일, 90일. 현재 복용 약과 기록 포함 여부를 고른 뒤 PNG 미리보기가 열림. 여기서 사진으로 저장하거나 다른 앱으로 보낼 수 있음. 시작일과 종료일을 직접 고르는 달력은 저장하지 않음 |
| 서비스 안내 및 정보 동의 | 이용약관, 개인정보 처리방침, 동의 안내 |
| 약통 관련 기기 찾기, 부저, LED, 동기화, 연결 해제 | 약통이 등록된 설정 화면 |

회원 탈퇴는 비밀번호 확인 후 진행됩니다. 본인 계정은 개인정보와 건강기록이 10분 이내 삭제된다는 안내가 있습니다. 대리인 탈퇴는 복약자 기록을 바로 지우지 않는다는 안내가 있습니다. 안내를 읽기 전에는 탈퇴하지 않습니다.

### 5. 약관

**서비스 안내 및 정보 동의**에서 문서를 읽습니다. 약 등록 동의는 약을 처음 등록할 때 따로 받습니다.

### 6. 보호자 연동

설정 첫 화면의 **복약자 연동 관리**는 가입 유형이 **대리인**일 때만 메뉴에 나옵니다. **본인**으로 가입한 계정에는 이 메뉴 줄이 없습니다.

들어가면 연동된 복약자 목록을 봅니다. 없을 때는 “연동된 복약자가 없습니다.”입니다. **연동 해제**는 연결을 끊습니다. 약을 지우지는 않습니다.

새 연동을 요청하는 초대 코드를 만드는 화면은 이 목록 코드에서 확인하지 못했습니다. **개발팀 확인 필요.** 목록에 없는 사람을 연결하려고 약을 다시 등록하지 않습니다.

### 7. 로그아웃과 계정

PART 1의 로그아웃과 비밀번호 변경을 사용합니다. 로그인 화면으로 돌아왔다고 서버의 약이 지워지지는 않습니다. 같은 아이디로 다시 로그인하면 서버에 있던 약이 다시 보여야 합니다.
