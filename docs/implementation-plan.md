# 구현 계획

이 문서는 순서와 의존성, 그리고 아직 확정하지 않은 구조 제안이다. 이 단계에서 코드를 작성하지 않는다. 데이터 모델과 화면 구조를 저장소의 구현으로 확정하지 않는다.

착수 조건: [open-questions.md](open-questions.md) 가운데 아래 "착수 전에 필요한 결정"이 정해진 뒤다. 사용자의 확인 없이 화면 구현으로 넘어가지 않는다.

## 현재 프로젝트에서 확인한 사실

저장소는 약연 화면을 다시 만들기 위한 Android 앱 껍질이다. 명세서의 화면, 복약 데이터, 내비게이션은 아직 없다.

| 항목 | 확인한 값 |
| --- | --- |
| 모듈 | `:app` |
| 루트 이름 | `yakyeon2` |
| applicationId, namespace | `com.example.yakyeon2` |
| 언어 | Java. `MainActivity` 하나 |
| UI | `activity_main.xml`의 `Hello World!` 텍스트. Jetpack Compose 의존성 없음 |
| 테마 | Material3 DayNight, NoActionBar. 색은 검정·흰색만 정의 |
| SDK | minSdk 26, compileSdk·targetSdk 37, Java 11 |
| 라이브러리 | AppCompat, Material, ConstraintLayout, Activity KTX |
| 테스트 | 예시 단위 테스트 `2 + 2`, 기기 테스트는 패키지명 확인 |
| 매니페스트 | 런처 액티비티 `MainActivity` 하나. 카메라·블루투스·알림 권한 선언 없음 |

피그마와 명세서의 화면은 이 코드에 연결되어 있지 않다. 기존 구현을 확장할 도메인 코드는 없다.

## 화면 의존성

화살표는 명세서에 적힌 이동만 의미한다. 질문으로 남은 이동은 점선으로 적는다.

```text
MDL-SIGNUP-GATE → SCR-SIGNUP-TYPE → SCR-SIGNUP-FORM → MDL-SIGNUP-SUCCESS → SCR-LOGIN
                         └ 대리인 → MDL-VIEW-CONSENT → SCR-SIGNUP-FORM

SCR-LOGIN → SCR-HOME → SCR-MED-LIST → SCR-MED-CONSENT → SCR-ENVELOPE
                └ 남은 복약 → SCR-SCHEDULE → MDL-TAKEN → MDL-ROUND
SCR-HOME의 병용금기·이번주 링크는 목적지 미정

SCR-ENVELOPE ‥ SCR-ENVELOPE-EDIT → MDL-ALARM-TIME → SCR-MED-LIST
                              └ 약통에 넣기 → SCR-SLOT → MDL-ALARM-TIME

SCR-MED-LIST 길게 누름 → MDL-MED-CARD → 수정확인 또는 시간오류 또는 삭제
SCR-MED-LIST 조기종료 → MDL-STOP-MED

MDL-IOT-GATE → (Q-01) 동의 2280:5315 또는 기기 찾기 2280:2993 → SCR-PILLBOX → SCR-PILLBOX-SET
SCR-PILLBOX-SET 연결 해제 확인 → MDL-IOT-GATE

SCR-SETTINGS → 프로필 / 연동(대리인만) / 알림 / 공유 / 권한(프레임 없음) / 법적 안내
법적 안내 → 이용약관, 개인정보 방침, 약물 동의 상세, 약통 연결 안내 (읽기 전용)
알림의 약통 상태 → 알림 · 02
공유 기간 → 기간 팝업
공유 내보내기 → (Q-03) PDF 문서 또는 PNG 미리보기

어느 화면이든 comment-alt → SCR-HISTORY (아이콘 위치는 Q-25)
그래프 탭 → (Q-02)
```

`복약 일정 · 02`는 새 목적지가 아니라 일정의 수동 기록 결과로 명세되어 있다. 구현 시 별도 라우트로 고정하지 말고, Q-10 이후에 같은 화면의 상태로 둘지 결정한다.

## 제안하는 구현 순서

순서는 의존이 적은 껍질부터다. 각 단계의 화면 동작은 화면 명세를 넘어서 채우지 않는다. Q 번호가 있는 단계는 그 답이 오기 전에 완료로 보지 않는다.

1. 앱 껍질과 공통 헤더. 헤더 볼드는 [common-design-rules.md](common-design-rules.md). 하단 탭은 피그마에서 탭 텍스트가 확인된 화면과 아닌 화면이 섞여 있으므로, 탭을 전 화면에 두기 전에 Q-02와 함께 적용 범위를 정한다.
2. 가입·로그인. MDL-SIGNUP-GATE부터 SCR-LOGIN까지. Q-04, Q-05, Q-22, Q-24가 팝업과 검증에 걸린다.
3. 홈과 약물 목록의 조회. 집계 규칙은 명세서의 개수·예정만·종료 구역을 따른다. 예시 약물명을 고정 데이터로 넣지 않는다.
4. 약 등록. 동의, 촬영 자리, 수기 입력, 칸, 알람 시각, 목록 복귀. Q-06, Q-07, Q-08, Q-15, Q-16, Q-22, Q-23.
5. 일정과 수동 기록, 복용 내역. Q-09, Q-10, Q-11, Q-25.
6. 설정 조회 화면과 읽기 전용 법적 문서. 조문 전문은 잘린 상태이므로 Q-26에서 원문을 받기 전에는 placeholder 전문을 만들어 넣지 않는다.
7. 프로필의 새 흐름, 연동, 알림 스위치. Q-13, Q-19, Q-20, Q-21, Q-24.
8. 스마트 약통. Q-01, Q-14, Q-15 이후. 연결 해제 확인은 프레임이 없고 명세서 문구만 있다.
9. 의료진 공유. Q-03, Q-18 이후. PDF 예시 수치를 실데이터처럼 넣지 않는다.
10. 약물 관계 그래프와 병용금기 상세. Q-02에서 포함하기로 한 경우에만.

## 공통으로 나눌 후보

확정된 컴포넌트 목록이 아니다. 화면 명세에 반복되어서 나눌 후보만 적는다.

| 후보 | 반복되는 곳 | 주의 |
| --- | --- | --- |
| 볼드 헤더와 뒤로 가기 | 피그마 상세 화면에 이전 화면 벡터가 있는 동의·설정 계열 | 탭 화면의 헤더와 모달 제목을 같은 컴포넌트로 강제하지 않음 |
| 하단 탭 | 탭 텍스트가 확인된 본 화면 | 적용 범위 미정 |
| 동의 스크롤과 필수 체크, 취소/진행 버튼 | 가입, 약 등록, 기기 연결 | 체크 개수와 진행 조건이 서로 다름. Q-16 |
| 두 버튼 확인 팝업 | 종료, 삭제 2종, 수정, 시간 오류, 명세서의 신규 팝업 | 버튼 문구가 취소/삭제, 아니요/네로 다름 |
| 약물 입력 폼 | 수기 수정, 알람 카드 | 삭제 팝업 목적지가 다름. Q-12 |
| 시간 선택 | 복용시간 알림, 몇 시에 드셨나요, 공유 기간의 달력 | 숨김 규칙과 읽기 전용 규칙이 화면마다 다름 |
| 온오프 행 | 알림, 약통 부저·LED, 권한 | 약통 상태 행은 이동도 겸함. Q-13 |

## 데이터 구조 제안

아래 이름과 관계는 제안이다. 저장 방식, 테이블, API는 정하지 않는다. 현재 앱에는 이 구조가 없다.

- 계정: 이름, 생년월일, 휴대폰, 아이디, 비밀번호, 유형(본인 또는 대리인). 마스킹은 표시 규칙이며 저장값과 분리하는 쪽이 명세서의 프로필 조건과 맞다. Q-19.
- 동의 기록: 가입 4종, 약 등록, 기기 정보, 철회 상태. 철회 버튼이 두 개인 약물 등록은 Q-17 전까지 한 레코드로 합치지 않는다.
- 약 카탈로그: 검색에 쓰는 저장된 약. 앱 안에 없다는 사실만 확인했다. 출처는 미정.
- 약봉투: 이름(처방 병원), 소속 약, 확인 완료 여부, 종료 여부, 남은 일수 계산의 기준일.
- 약: 카탈로그 참조, 복용량, 아침·점심·저녁, 복용 시점, 기간. 시작일 제약은 Q-23.
- 회차 기록: 날짜, 예정 시각, 상태, 수동 시각, 기록 경로(직접 또는 약통). 상태 전이는 Q-10 전까지 하나의 상태 기계로 확정하지 않는다.
- 약통: 기기 이름, 연결 상태, 칸 3개의 점유, 부저, LED, 마지막 동기화 시각.
- 알림 설정: 명세서의 8개 스위치를 한 설정 객체로 둘 수 있다. `· 02`를 대리인 전용으로 묶을지는 Q-13.
- 연동: 복약자 성명, 관계, 전화번호, 나이. 나이는 Q-20.
- 공유 선택: 기간과 항목별 포함 여부. `전체`와 포함/제외는 Q-18 전까지 같은 필드로 합치지 않는다.

## 화면 상태

제안일 뿐 상태 관리 라이브러리를 고르지 않는다.

- 가입 유형, 동의 체크, 인증 카운트다운, 약 확인 체크, 칸 선택, 알림 스위치, 공유 토글은 각 화면의 입력 상태다.
- 복약 일정 `· 02`는 별도 영구 화면이라기보다 기록 반영 후의 일정 표시다.
- 약통 칸 점유는 등록 흐름과 약통 화면이 같이 본다.
- 대리인 여부는 설정 메뉴의 연동 항목 노출에 쓴다.
- 피그마의 김약연, 약1–약9, 92.9%는 상태의 초기값으로 넣지 않는다. 빈 목록과 0칸이 명세서에 있는 초기 조건이다.

## 내비게이션

라이브러리를 정하지 않는다. 현재는 액티비티 하나다.

- 명세서에 이름이 있는 이동만 목적지로 연결한다.
- Q 번호가 붙은 목적지는 임시 화면으로 단정하지 않고, 결정 전까지 라우트를 비워 둔다.
- 읽기 전용 4화면은 설정 안내에서만 들어간다.
- 복용 내역은 탭이 아니라 comment-alt 진입으로 명세되어 있다. 위치는 Q-25.
- 연결 해제 확인 뒤에는 연결 전 팝업으로 돌아간다.

## UI 기술 선택

정하지 않는다. 현재 모듈은 XML 레이아웃과 Java다. Compose로 바꿀지, XML로 화면을 쌓을지는 구현 착수 때의 선택이며 이 분석이 정한 구조가 아니다. 어느 쪽을 골라도 화면 명세의 조건은 같다.

권한 선언이 필요할 수 있는 기능은 카메라 촬영, 알림, 블루투스 또는 근처 기기, 명세서의 와이파이 상태 표시다. 어떤 권한을 매니페스트에 넣을지는 Q-14와 Q-21 이후다. 지금 매니페스트에는 없다.

## 테스트가 필요한 조건

코드를 추가하지 않는다. 예시 테스트는 이 조건과 무관하다. 구현 뒤에 최소로 확인할 조건만 적는다.

- 가입 체크가 하나라도 비면 유형 선택으로 가지 않는다.
- 유형 미선택 문구, 본인/대리인 단일 선택.
- 필수 항목 누락 시 빠진 항목이 문구에 들어간다.
- 가입된 번호, 중복 아이디, 비유효 비밀번호는 오류 팝업. 성공은 성공 팝업 뒤 로그인.
- 로그인 실패 문구가 명세서 문장과 같다.
- 홈 개수, 예정만 남은 오늘 목록, 시간대 바와 아이콘.
- 사용 중 칸은 선택되지 않는다.
- 선택하지 않은 아침·점심·저녁은 알람 시각 입력에 나오지 않는다. 약마다 다른 경우는 Q-08 이후의 기대값을 쓴다.
- 이전 회차는 알림 시각 3시간 뒤에 선택할 수 없다. 그 이후 자동 표시는 명세 기준으로 누락이다. 지연 표시를 기대값에 넣을지는 Q-10 이후다.
- 수정 완료의 두 갈래. 4시간과 버튼 의미는 Q-11 이후의 기대값을 쓴다.
- 알람 카드 삭제와 수기 수정 삭제가 명세서가 가리킨 팝업으로 간다.
- 대리인이 아닐 때 연동 메뉴가 없다.
- 알림 스위치는 항목별로 독립이다.
- 포함/제외는 한 항목에서 동시에 켜지지 않는다. 현재 약물 항목은 Q-18 이후.
- 법적 상세에 편집 동작이 없다.
- 연결 해제 확인 뒤 목적지가 연결 전 팝업이다.

## 착수 전에 필요한 결정

화면 뼈대만 만드는 일과 데이터 규칙을 구현하는 일이 다르다. 아래가 남으면 해당 흐름의 구현을 완료로 두지 않는다.

1. Q-01 약통 연결 순서.
2. Q-02 그래프 탭과 병용금기 화면의 포함.
3. Q-03 공유 파일 형식.
4. Q-04, Q-05 가입 유형과 대리인 QR.
5. Q-06부터 Q-12 약물 등록·일정 상태·시간 검증.
6. Q-16 약 등록·기기 동의의 체크 조건.
7. Q-22, Q-23 선택 목록, 비밀번호 규칙, 받은 날.
8. Q-26 약관 전문. 잘린 본문을 완성된 법적 문구로 쓰지 않는다.

그 밖의 질문도 해당 화면을 만들기 전에 필요하다. 질문 목록 전체를 구현 중 임의로 고르지 않는다.

## 이번 분석에서 구현 근거로 쓰지 못하는 범위

- 긴 약관·방침·동의 문장의 잘린 뒷부분.
- 헤더별 실제 font-weight, 색, 치수 토큰.
- 화면 밖 이미지 `2305:70`의 내용.
- 권한 웹의 전체 URL.
- comment-alt의 위치.
- 인증번호, OCR, 약 데이터베이스, 기기 검색의 실제 연동 방식. 명세서가 결과를 정한 부분까지만 요구사항이다.
