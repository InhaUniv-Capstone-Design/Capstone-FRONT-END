# 약연 문제 해결 가이드

앱 버전 3.0을 기준으로 썼습니다. 화면 문구는 앱에 있는 문장만 적었습니다. 코드만으로 원인을 단정할 수 없으면 **개발팀 확인 필요**라고 적습니다.

## 먼저 지킬 것

- 앱을 삭제하거나 앱 데이터를 지우지 않습니다. 로그인 계정과 서버의 약이 어긋날 수 있습니다.
- 같은 약을 한 번 더 등록하지 않습니다. 목록에 안 보여도 서버에는 저장되어 있을 수 있습니다.
- **삭제**, **종료**, **회원 탈퇴**, **연결 해제**는 확인 창의 문장을 읽기 전에는 누르지 않습니다. 약통의 **칸 비우기** 확인 버튼은 **삭제**라고 보이지만, 문장은 “약통 배정을 해제합니다”입니다. 약 목록에서 약을 지우는 동작과 다릅니다.
- 시리얼, 비밀값, 비밀번호, 인증번호는 채팅에 붙이지 않습니다. 개발팀에는 “틀렸다”만 알리고 값은 보내지 않습니다.

## 개발팀에 전달할 정보

문제가 남으면 아래를 한 메시지에 모읍니다.

| 항목 | 적을 내용 |
| --- | --- |
| 날짜와 시간 | 문제가 난 시각. 가능하면 분까지 |
| 스마트폰 | 기종 이름 |
| Android 버전 | 휴대폰 설정에서 확인 |
| 앱 버전 | 앱 안에 버전 숫자를 보여 주는 메뉴는 확인하지 못했습니다. 설치한 파일 이름 `Yakyeon_Test_v3.0.apk`와, 휴대폰 **설정 > 앱 > yakyeon2**의 버전을 적습니다 |
| 메뉴 | 홈, 복약 일정, 그래프, 약통, 설정, 내 약물, 로그인 중 어디인지 |
| 직전 행동 | 누른 버튼 이름 |
| 화면 | 보인 문장을 그대로. 스크린샷이 있으면 첨부 |
| 재현 | 같은 순서로 다시 되는지 |
| 재현 순서 | 1, 2, 3으로 |

오류는 아래 셋 중 어디에 가까운지 같이 적습니다.

| 구분 | 화면에 가까운 모습 |
| --- | --- |
| 서버 연결 오류 | “서버에 연결할 수 없습니다. 네트워크를 확인한 뒤 다시 시도해 주세요.” 앱은 꺼지지 않습니다 |
| API 오류 | 연결은 되는데 “필수 항목을 입력해주세요”, “인증번호가 일치하지 않습니다.”처럼 서버나 입력 검사 문장이 나옴 |
| 기기 연동 오류 | 앱은 열리는데 약통이 **오프라인**이거나, 칸 배정과 약통 LCD가 다름. LCD 문장은 앱이 그리지 않습니다 |

## 읽는 방법

각 문제는 다음 순서입니다.

1. 지금 화면에 그 증상이 맞는지 확인합니다.
2. 사용자가 직접 볼 수 있는 항목을 확인합니다.
3. 데이터를 지우지 않는 조치만 합니다.
4. 안 되면 추가로 남길 정보를 적습니다.
5. 그 내용을 개발 담당자에게 보냅니다.

## 회원가입 및 로그인

### 인증번호가 전송되지 않음

| 증상 | 가능한 원인 | 확인 방법 | 해결 방법 |
| --- | --- | --- | --- |
| **인증번호 받기** 뒤에 문자가 없음 | 번호 형식, 요청 횟수, 서버가 문자 대신 “문자 앱으로 보내기”를 준 경우, 네트워크 | 화면에 “인증번호를 보냈습니다.”가 있는지, 큰 숫자 코드와 **문자 앱으로 보내기**가 있는지 | 아래 순서 |

1. 증상: 문자가 없고, 화면에 보낸다는 문장도 없는지 봅니다.
2. 확인: 번호가 010으로 시작하는 11자리인지, “요청이 너무 많습니다”가 있는지, “서버에 연결할 수 없습니다”가 있는지 봅니다.
3. 조치: 번호가 맞으면 한 번만 다시 **인증번호 받기**를 누릅니다. 화면에 코드와 **문자 앱으로 보내기**가 있으면 그 코드를 안내된 번호로 보냅니다. 코드 외의 글자는 넣지 않습니다.
4. 추가 확인: 같은 번호로 다른 휴대폰에서도 문자가 없는지, 시각을 적습니다.
5. 전달: 가입인지 아이디 찾기인지, 화면에 보인 문장, 문자가 왔는지 여부. 인증번호 숫자는 보내지 않습니다.

### 인증번호가 입력되지 않음

| 증상 | 가능한 원인 | 확인 방법 | 해결 방법 |
| --- | --- | --- | --- |
| 숫자 칸이 안 보이거나 입력이 안 됨 | 인증이 이미 끝나 칸이 숨겨짐, 문자 보내기 방식 화면, 키보드가 다른 칸에 있음 | “인증이 완료되었습니다”가 있는지, 큰 코드가 있는지 | 아래 순서 |

1. 증상: 6자리를 넣을 칸이 있는지 봅니다.
2. 확인: 완료 문구가 있으면 그 번호는 이미 인증된 것입니다. 큰 코드만 있으면 앱에 숫자를 넣는 방식이 아닙니다.
3. 조치: 완료 문구가 있으면 가입을 계속합니다. 큰 코드만 있으면 **문자 앱으로 보내기**를 사용합니다. 칸이 있는데 숫자가 아니면 “인증번호는 숫자 6자리입니다.”가 납니다.
4. 추가 확인: 칸을 눌렀을 때 키보드가 숫자 키보드인지.
5. 전달: 화면 스크린샷. 받은 인증번호는 가립니다.

### 인증번호 입력 후 다음 단계로 넘어가지 않음

| 증상 | 가능한 원인 | 확인 방법 | 해결 방법 |
| --- | --- | --- | --- |
| 숫자를 넣어도 가입·찾기가 진행되지 않음 | 인증 전 제출, 번호 불일치, 만료, 다른 필수칸 | 화면에 나온 문장 | 문장에 맞는 한 가지만 다시 함 |

1. 증상: 누른 버튼과 그 직후 문장을 확인합니다.
2. 확인: “인증번호를 먼저 요청해 주세요.”, “인증번호를 입력해 주세요.”, “인증번호가 일치하지 않습니다.”, “인증 시간이 만료되었습니다.”, “휴대폰 번호가 바뀌었습니다.” 중 무엇인지 봅니다.
3. 조치: 만료이거나 번호가 바뀌었으면 **인증번호 받기**부터 다시 합니다. 불일치면 같은 문자의 6자리만 다시 넣습니다. 가입이면 아이디 **중복 확인**과 비밀번호 규칙도 봅니다. 비밀번호는 영문, 숫자, 특수문자 포함 8~64자입니다.
4. 추가 확인: 문자를 받은 시각과 입력한 시각의 차이.
5. 전달: 버튼 이름과 문장. 인증번호와 비밀번호는 빼고 적습니다.

### 입력창을 누르면 키보드가 사라짐

| 증상 | 가능한 원인 | 확인 방법 | 해결 방법 |
| --- | --- | --- | --- |
| 칸을 누르자마자 키보드가 닫힘 | 뒤로 가기가 키보드를 먼저 닫음, 화면이 다시 그려짐 | 뒤로 가기를 눌렀는지, 어느 칸인지 | 아래 순서. 앱 데이터는 지우지 않음 |

1. 증상: 아이디, 비밀번호, 인증번호 중 어느 칸인지 확인합니다.
2. 확인: 인증이 끝나면 인증번호 칸은 숨겨집니다. 그때 그 칸이 사라진 것은 키보드 고장이 아닙니다. 뒤로 가기는 화면을 나가기 전에 키보드만 닫도록 되어 있습니다.
3. 조치: 칸을 한 번 더 눌러 키보드를 띄웁니다. 스크롤만 하고 칸 안을 다시 누릅니다. 인증 타이머가 1초마다 돌아도 아이디·비밀번호 키보드를 닫지 않도록 되어 있습니다. 그래도 닫히면 그 사실을 적습니다.
4. 추가 확인: 가입 화면인지, 아이디 찾기인지, 누른 칸 이름, Android 버전.
5. 전달: 재현 순서. **개발팀 확인 필요:** 특정 기종에서만 다시 열리는지는 코드만으로 단정하지 않습니다.

### 회원가입이 완료되지 않음

| 증상 | 가능한 원인 | 확인 방법 | 해결 방법 |
| --- | --- | --- | --- |
| 가입 버튼 후 로그인 화면으로 안 감 | 필수값, 아이디 중복, 인증, 비밀번호 규칙, 네트워크 | 짧은 안내 문장 | 그 문장의 항목만 수정 |

1. 증상: “가입되었습니다. 로그인해 주세요.”가 없었는지 확인합니다.
2. 확인: 본인/대리인 선택, 이름, `YYYY.MM.DD` 생년월일, 휴대폰, 아이디 6~20자 영문·숫자, 중복 확인, 비밀번호와 확인이 같은지.
3. 조치: “사용할 수 있는 아이디입니다.”가 나오기 전에는 가입을 끝내지 않습니다. 네트워크 문장이면 Wi-Fi나 모바일 데이터를 확인한 뒤 같은 입력으로 한 번만 다시 누릅니다. 여러 번 누르면 “요청이 너무 많습니다”가 날 수 있습니다.
4. 추가 확인: 마지막에 보인 문장 한 줄.
5. 전달: 가입 유형과 문장. 비밀번호는 보내지 않습니다.

### 로그인이 되지 않음

| 증상 | 가능한 원인 | 확인 방법 | 해결 방법 |
| --- | --- | --- | --- |
| **로그인** 후 아래 탭이 안 나옴 | 아이디·비밀번호, 잠금, 네트워크 | 문장 | 아래 순서 |

1. 증상: 로그인 화면에 그대로 있는지 봅니다.
2. 확인: “로그인 시도가 너무 많아요. 15분 뒤에 다시 시도해주세요.”인지, 네트워크 문장인지, 다른 오류 문장인지 봅니다. 아이디는 100자, 비밀번호는 128자를 넘기면 별도의 길이 안내가 있습니다.
3. 조치: 잠금 문장이면 15분 동안 다시 누르지 않습니다. 비밀번호를 잊었으면 로그인 화면의 **비밀번호 재설정**을 사용합니다. 앱을 지우지 않습니다.
4. 추가 확인: 아이디 찾기 결과와 로그인에 넣은 아이디가 같은지. 아이디 전체를 채팅에 붙이지 않아도 되면 앞 두 글자만 적어도 됩니다.
5. 전달: 문장, 잠금 여부, 시각.

## 약물 등록

### 약물 등록 버튼이 작동하지 않음

| 증상 | 가능한 원인 | 확인 방법 | 해결 방법 |
| --- | --- | --- | --- |
| **추가 등록**, **촬영하기**, **약통에 넣기**가 반응이 없음 | 약 등록 동의가 안 끝남, 로그인 만료, 화면이 로딩 중 | 동의 체크 두 개, 로딩 문구 | 동의 후 다시 진입 |

1. 증상: 누른 버튼 이름을 확인합니다.
2. 확인: “(필수) 복약정보 수집·이용에 동의합니다.”와 “(필수) 서비스 이용 고지를 확인했습니다.”가 체크됐는지, “약 등록 동의 버전을 서버 약관에서 찾지 못했습니다”가 있는지 봅니다.
3. 조치: 두 필수 항목을 체크하고 **동의하고 약 등록**을 누릅니다. 버전을 찾지 못했다는 문장이면 등록을 반복하지 않고 개발팀에 그 문장을 보냅니다.
4. 추가 확인: 로그인 상태인지, 홈 탭이 보이는지.
5. 전달: 버튼 이름과 문장.

### 필수 항목을 입력했는데 등록되지 않음

| 증상 | 가능한 원인 | 확인 방법 | 해결 방법 |
| --- | --- | --- | --- |
| “필수 항목을 입력해주세요” 또는 시간 오류 | 병원명, 확인 완료, 용량 0, 날짜, 식전·식후 개수, 4시간 간격 | [USER_MANUAL.md](USER_MANUAL.md) PART 2 표 | 표의 한 칸씩 다시 봄 |

1. 증상: 문장이 “필수 항목을 입력해주세요”인지 “확인완료에 체크해주세요”인지 “복용 시간이 올바르지 않습니다.”인지 구분합니다. 안내는 짧게 사라질 수 있습니다.
2. 확인: 병원명, 약마다 이름·용량·시작일·종료일·**확인 완료**, 아침·점심·저녁이 있으면 식전·식후·식사와 함께 중 하나, 회차 사이 4시간, 아침·점심·저녁은 20:59까지, 취침은 23:59까지.
3. 조치: 해당 칸만 고치고 다시 저장합니다. 용량 0은 저장되지 않습니다. 정은 0.5·1·2·3, 캡슐은 1·2만 됩니다. 기간은 시작일 포함 1일 이상 365일 이하입니다.
4. 추가 확인: 어느 약을 고쳤는지. 약을 새로 추가하지 않습니다.
5. 전달: 약 개수, 고른 회차, 시작·종료일, 문장. 용량 숫자가 규칙 밖이면 그 숫자도 적습니다.

### 어떤 항목이 필수인지 알 수 없음

회원가입은 `*`가 있습니다. 약 등록 화면은 항목마다 필수 표시가 따로 붙지 않을 수 있습니다. 필수는 사용자 매뉴얼 PART 2의 표를 봅니다. 병원명, 약물명, 용량, 기간, 복용 횟수, 식사 회차가 있을 때의 복용 시점, 확인 완료, 고른 회차의 시각이 필수입니다. 약국명과 약통 칸은 약통 없이 등록할 때 필수가 아닙니다.

### 복용 횟수나 복용 시점을 선택할 수 없음

| 증상 | 가능한 원인 | 확인 방법 | 해결 방법 |
| --- | --- | --- | --- |
| 아침 등이 체크되지 않거나 식전이 같이 켜짐 | **필요 시**와 회차가 겹침, 식전·식후·함께를 둘 이상 선택 | 켜진 칩 | 하나만 남김 |

1. 증상: 안 켜지는 칩 이름을 확인합니다.
2. 확인: **필요 시**가 켜져 있으면 아침·점심·저녁·취침과 같이 쓰지 않습니다. 식사 회차가 있으면 식전, 식후, 식사와 함께 중 하나만 남깁니다. 취침만이면 그 세 개를 고르지 않습니다.
3. 조치: 약봉투와 같은 조합만 남기고 **확인 완료**를 다시 체크합니다.
4. 추가 확인: 칩이 화면에 없는지, 눌러도 색이 안 바뀌는지.
5. 전달: 스크린샷. 조합 규칙 밖에 약봉투가 있으면 약 이름을 적고 개발팀에 묻습니다. 임의로 다른 횟수로 저장하지 않습니다.

### 복용 시작일과 종료일을 잘못 입력함

1. 증상: 저장 전인지, 이미 **내 약물**에 올라갔는지 확인합니다.
2. 확인: 종료일이 시작일보다 이른지, 기간이 365일을 넘는지.
3. 조치: 아직 최종 등록 전이면 날짜만 다시 고릅니다. 이미 등록됐다면 이름과 용량을 다시 고치는 화면은 확인하지 못했습니다. **개발팀 확인 필요.** 같은 약을 한 번 더 등록하지 않습니다. 종료나 삭제는 매뉴얼의 확인 창을 읽기 전에는 누르지 않습니다.
4. 추가 확인: 시작일, 종료일, 약 이름.
5. 전달: 그 세 가지와, 저장 전인지 후인지.

### OCR이 약물 정보를 잘못 인식함

1. 증상: 이름, 용량, 횟수 중 약봉투와 다른 칸을 표시합니다.
2. 확인: “서버가 돌려준 인식 초안입니다. 실제 판독 서비스 결과가 아니면 내용을 확인한 뒤 등록해 주세요.”가 있는지 봅니다. OCR 결과는 맞는 값이 아닙니다.
3. 조치: **확인 완료** 전에 칸을 직접 고칩니다. 인식이 비어 있으면 “인식된 약이 없습니다. 직접 입력해 주세요.”가 납니다. 그때 **추가 등록**으로 줄을 만듭니다.
4. 추가 확인: 이미 저장했다면 목록의 그 봉투를 엽니다. 새 봉투를 만들지 않습니다.
5. 전달: 약봉투에서 가린 뒤의 사진, 앱에 들어간 값, 저장 전인지.

### OCR 결과가 일부 누락됨

용량, 횟수, 일수가 비어 있어도 약 이름이 있으면 줄은 남습니다. 앱이 빈 값을 0이나 1로 채우지 않습니다. 비어 있는 칸을 약봉투대로 입력한 뒤 **확인 완료**를 합니다. 하루 횟수만 있고 시간대가 없으면 아침부터 취침 순으로 횟수만큼 초안 체크가 될 수 있습니다. 저장 전에 약봉투와 비교합니다.

### 등록한 약물이 목록에 나타나지 않음

| 증상 | 가능한 원인 | 확인 방법 | 해결 방법 |
| --- | --- | --- | --- |
| **내 약물**에 방금 약이 없음 | 저장 문장 없이 화면만 닫힘, 다른 계정, 종료 목록, 네트워크 | 맨 위 봉투, **복용 종료한 약물** | 다시 등록하지 말고 아래로 |

1. 증상: 최종 등록을 누른 뒤 목록으로 왔는지 확인합니다.
2. 확인: 목록 맨 위, 종료된 약 구역, 로그인 아이디가 등록할 때와 같은지. “서버에 연결할 수 없습니다”가 있었는지.
3. 조치: 홈을 나갔다가 **내 약물**을 다시 엽니다. 그래도 없으면 같은 약을 다시 만들지 않습니다.
4. 추가 확인: 등록 시각, 병원명, 약 이름.
5. 전달: 그 정보와 저장 버튼을 눌렀는지.

### 약물 수정 및 삭제가 되지 않음

등록 후 이름·용량·기간을 고치는 화면은 확인하지 못했습니다. 있는 동작은 **복용 시간 수정**, 칸 변경, 약 줄을 짧게 눌러 **약 복용 종료**, 약 줄을 길게 눌러 **삭제**, 봉투의 **복용 조기 종료하기**입니다. 종료된 봉투는 시간 수정과 칸 변경이 사라집니다.

1. 증상: 누른 동작이 위 목록에 있는지 봅니다.
2. 확인: 봉투에 **복용 종료**가 있는지, 짧게 눌렀는지 길게 눌렀는지.
3. 조치: 시간만 바꾸려면 **복용 시간 수정**을 씁니다. 종료와 삭제는 확인 창을 읽은 뒤에만 합니다. 지난 기록은 남는다는 문장이 있습니다.
4. 추가 확인: 약 이름과 누른 방식.
5. 전달: 바꾸려는 항목이 이름·용량·기간이면 그 사실을 적습니다. 임의로 삭제하지 않습니다.

## 약통 관리

### 약통이 등록되지 않음

1. 증상: **기기 찾기** 이후에도 “연결된 약통이 없어요”인지 봅니다.
2. 확인: **약통 라벨의 시리얼번호**와 **약통 라벨의 비밀값**을 라벨과 한 글자씩 비교합니다. 네트워크 문장이 있는지도 봅니다.
3. 조치: 값을 다시 입력해 한 번만 등록합니다. 이미 **연결됨**이면 다시 등록하지 않습니다.
4. 추가 확인: 약통 전원, 약통 화면의 와이파이 표시. 약통이 서버에 붙는 와이파이 입력 순서는 이 앱만으로 확인하지 못했습니다. **개발팀 확인 필요.**
5. 전달: 등록 시각과 화면에 남은 문장. 시리얼과 비밀값은 보내지 않습니다.

### 시리얼 번호 또는 인증 정보가 일치하지 않음

라벨과 다른 값을 고쳐서 다시 한 번만 입력합니다. 실패 문장이 있으면 그 문장을 남깁니다. 맞는 값을 찾기 위해 여러 번호를 연속으로 넣지 않습니다.

### 약물과 약통 칸이 배정되지 않음

| 증상 | 가능한 원인 | 확인 방법 | 해결 방법 |
| --- | --- | --- | --- |
| 칸을 눌러도 배정되지 않음 | 약통 미등록, 칸이 사용 중, 네트워크 | “연결된 약통이 없어 칸을 배정하지 않습니다.”, “사용 중인 칸은 선택할 수 없습니다.” | 빈 칸만 선택 |

1. 증상: 자물쇠가 있는 칸인지 빈 칸인지 봅니다.
2. 확인: 사용 중 칸은 새 약봉투에 배정되지 않습니다. 그 약을 이미 쓰는 칸만 칸 변경에서 다시 고를 수 있습니다.
3. 조치: **비어 있음**인 칸을 고릅니다. 약통이 없으면 먼저 **기기 찾기**로 등록합니다. 칸 없이 쓰려면 등록 화면의 **약통 없이 사용하기**를 씁니다. 실패했다고 같은 약을 다시 등록하지 않습니다.
4. 추가 확인: 칸 번호, 그 칸에 이미 보이는 병원 이름.
5. 전달: 칸 번호와 문장.

### 기존에 배정된 칸이 해제되지 않음

1. 증상: **칸 비우기** 후 “약통 칸의 배정이 해제되었어요.”가 있었는지 봅니다.
2. 확인: 확인 버튼 글자는 **삭제**입니다. 본문이 배정 해제인지 읽고 눌렀는지 확인합니다.
3. 조치: 문장이 없었으면 한 번만 다시 **칸 비우기**를 합니다. 약 목록의 길게 눌러 삭제와 섞지 않습니다.
4. 추가 확인: 약통 탭을 다시 열었을 때 그 칸이 **비어 있음**인지.
5. 전달: 칸 번호와 전후 스크린샷.

### 약통 상태가 정상적으로 표시되지 않음

약통 탭은 서버가 준 상태를 보여 줍니다. **정상**, **충전 대기**, **확인 필요**, **약통이 열렸습니다.**, **연결됨**, **오프라인**이 있습니다. 로딩 중이면 “약통 정보를 불러오는 중입니다.”가 나옵니다. “등록된 약통 정보를 확인하지 못했습니다.”이면 약을 지우지 말고 그 문장과 시각을 전달합니다.

**기기 동기화**를 누른 뒤 “서버에 동기화를 접수했습니다. 기기가 받았는지는 이 응답으로 확인되지 않습니다.”가 나오면, 접수와 기기 반영은 별개입니다.

### 실제 약통과 앱의 상태가 다름

1. 증상: 약이 들어 있는 칸 번호와 앱의 칸 번호, LCD 문장을 따로 적습니다.
2. 확인: LCD의 `TAKEN` 같은 글자는 약통이 그립니다. 앱 홈이 바뀌기 전에는 앱 기록이 갱신된 것이 아닙니다.
3. 조치: 앱에서 약을 다시 등록하거나 칸을 연속으로 비우지 않습니다. 홈을 다시 열어 서버 값을 한 번 더 봅니다. 약통 버튼을 누른 시각과 앱을 본 시각을 적습니다.
4. 추가 확인: **기기 동기화** 줄의 문장.
5. 전달: 칸 번호, LCD 문장, 앱 문장, 두 시각. 앱이 약통 화면 글자를 직접 바꾸지는 않습니다.

## 복용 관리

### 복용 일정이 나타나지 않음

1. 증상: 홈인지 **복약 일정**인지 확인합니다.
2. 확인: 약의 시작일·종료일에 오늘이 들어가는지, 고른 회차가 있는지, 봉투가 **복용 종료**인지. 로그인 상태인지.
3. 조치: **복약 일정**에서 오늘 날짜를 다시 고릅니다. 약을 중복 등록하지 않습니다.
4. 추가 확인: 약 이름, 회차, 기간.
5. 전달: 홈은 비었는데 일정 탭에는 있는지, 둘 다 없는지.

### 복용 완료 체크가 되지 않음

1. 증상: **드셨나요?**가 없는지, 목록은 있는데 저장이 안 되는지 구분합니다.
2. 확인: “오늘 기록만 입력·수정할 수 있습니다.”, “3시간이 지나 선택할 수 없습니다.”, 네트워크 문장.
3. 조치: 홈의 **드셨나요?**로 목록을 연 뒤 한 약을 고르고, “몇시에 드셨나요?”에서 오늘 시각을 고른 다음 **수동으로 기록하기**를 누릅니다. 미래 시각은 선택되지 않습니다. 약이 하나여도 목록이 먼저 열립니다.
4. 추가 확인: 저장 후 목록으로 돌아왔는지. 남은 약이 있으면 다음 약의 시각 창이 자동으로 열리지 않는 것이 맞습니다.
5. 전달: 약 이름, 예정 시각, 막힌 문장.

### 복용 여부가 잘못 표시됨

1. 증상: 홈, **복약 일정**, 약통 LCD 중 어디가 다른지 적습니다.
2. 확인: 수동으로 넣은 시각과 약통 버튼을 누른 시각.
3. 조치: 다른 시각으로 덮어 쓰지 않습니다. 3시간이 지난 기록은 앱에서 고르지 못합니다. 스크린샷만 남깁니다.
4. 추가 확인: “복용 기록이 저장되었습니다.”를 봤는지.
5. 전달: 세 화면의 문장과 시각. 지연으로 보이는 기준 분은 서버가 정합니다. **개발팀 확인 필요.**

### 오늘 복용 현황과 그래프가 다름

그래프는 복용 완료 횟수를 세지 않습니다. “함께 복용 중인 약의 병용금기 등재 여부만 표시합니다.” 홈의 “병용금기 등재 정보가 N건 있어요”와 그래프의 등재 표시를 비교합니다. 복용을 체크했다고 그래프 점 개수가 늘지는 않습니다. 검사를 마치지 못한 약을 누르면 “이 약은 병용금기 검사를 마치지 못했습니다.”가 나올 수 있습니다.

### 캘린더에 기록이 나타나지 않음

아래 탭에 캘린더라는 이름은 없습니다. 달력 아이콘과 **복약 일정** 탭이 날짜별 일정입니다. 그 날짜에 일정이 없으면 목록이 비어 있습니다. 별도의 복용 내역 화면으로 들어가는 버튼은 확인하지 못했습니다. **개발팀 확인 필요.**

## 알림 및 네트워크

### 푸시 알림이 오지 않음

| 증상 | 가능한 원인 | 확인 방법 | 해결 방법 |
| --- | --- | --- | --- |
| 복용 시각이 됐는데 알림이 없음 | 휴대폰 알림 권한, 설정 스위치, 서버가 보내지 않음 | **설정 > 알림 설정**, 휴대폰 앱 알림 | 스위치와 권한만 확인 |

1. 증상: 기대하던 알림 종류를 적습니다. 복용 시간, 미복용, 종료 예정, 약통 중 무엇인지.
2. 확인: 설정에 “기기의 알림 권한이 꺼져 있으면 알림을 받을 수 없어요.”가 있는지. 해당 스위치가 켜져 있는지. 도움말은 복용 10분 전, 미복용 30분 후, 종료 3일 전입니다. 이 문장이 서버의 실제 발송 시각과 같은지는 **개발팀 확인 필요**입니다. 앱이 그 시각에 알람을 예약하는 화면은 없습니다.
3. 조치: 휴대폰 **설정 > 앱 > yakyeon2 > 알림**을 켭니다. 앱 안의 해당 스위치를 켭니다. 앱을 재설치하지 않습니다.
4. 추가 확인: 같은 시각에 앱 홈에는 일정이 있는지.
5. 전달: 켠 스위치 이름, 권한 상태, 기대한 시각, 실제 시각.

### 서버 연결 오류가 발생함

“서버에 연결할 수 없습니다. 네트워크를 확인한 뒤 다시 시도해 주세요.”이면 휴대폰의 Wi-Fi 또는 모바일 데이터를 확인한 뒤 같은 동작을 한 번 다시 합니다. 앱은 그때 꺼지지 않는 것이 맞습니다. 데이터가 안 바뀌었다고 약을 다시 등록하지 않습니다.

### 앱 로딩이 계속됨

1. 증상: “약통 정보를 불러오는 중입니다.”처럼 로딩 문장이 남는지, 빈 화면인지 봅니다.
2. 확인: 다른 탭은 열리는지, 네트워크 문장이 뒤늦게 나오는지.
3. 조치: 한 번만 다른 탭으로 갔다가 돌아옵니다. 앱을 강제 종료해야 하면 그 사실을 적고, 삭제는 하지 않습니다.
4. 추가 확인: 로딩이 시작된 메뉴와 기다린 시간.
5. 전달: 메뉴, 시간, 마지막 문장.

### 데이터가 갱신되지 않음

약통에서 복용 버튼을 누른 직후 앱이 다른 저장 중이면, 그 알림으로 홈을 바로 다시 읽지 않을 수 있습니다. 잠시 뒤 홈을 다시 엽니다. 그래도 그대로이면 스크린샷과 버튼 시각을 전달합니다. 당겨서 새로고침 같은 별도 버튼은 이 안내에서 확인하지 못했습니다. **개발팀 확인 필요.**

### 앱 실행 중 갑자기 종료됨

1. 증상: 종료 직전 화면과 누른 버튼을 적습니다.
2. 확인: 다시 열었을 때 로그인 화면인지, 홈인지. 약이 사라졌는지. 사라졌다고 바로 다시 등록하지 않습니다.
3. 조치: 같은 버튼만 한 번 더 눌러 재현되는지 봅니다. 반복해서 강제 종료되면 멈춥니다.
4. 추가 확인: 기종, Android 버전, 시각.
5. 전달: 재현 순서. 앱이 남기는 오류 기록 화면은 확인하지 못했습니다.

### 에뮬레이터에서는 되지만 실제 스마트폰에서는 작동하지 않음

1. 증상: 되는 동작과 안 되는 동작을 하나씩 적습니다.
2. 확인: 휴대폰 앱 버전이 3.0인지, 알림 권한, 카메라 권한, 네트워크 문장. 카메라가 없으면 **갤러리에서 선택**으로 약봉투 사진을 넣습니다.
3. 조치: 같은 APK를 덮어씁니다. 서명이 달라 설치가 거절되면 그때만 기존 앱을 지웁니다. 지우기 전에 개발팀에 알립니다. 서버 주소는 배포 서버입니다. 컴퓨터의 localhost는 휴대폰에서 동작하지 않습니다.
4. 추가 확인: 에뮬레이터와 휴대폰의 차이. 약통은 실제 기기가 계정에 연결돼 있을 때만 버튼 기록이 옵니다.
5. 전달: 기종, 안 되는 메뉴, 휴대폰에서만 보인 문장.
