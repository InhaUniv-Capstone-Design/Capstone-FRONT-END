# 화면 구현 명세

분석용 화면 ID다. 코드의 클래스명이나 라우트명으로 확정하지 않는다.

공통 헤더 굵기는 화면에 반복하지 않는다. [common-design-rules.md](common-design-rules.md)를 따른다. 여러 화면이 나누어 가지는 조건은 [business-rules.md](business-rules.md)를 따른다. 원문 표현은 [requirements-from-user.md](requirements-from-user.md)를 따른다.

각 화면의 `피그마` 행은 레이어 메타데이터에서 확인한 범위다. 색, 굵기, 잘린 문장의 뒷부분은 확인하지 못했다.

## 가입과 로그인

### SCR-LOGIN 화면 / 스플래시·로그인

- 진입: 명세서가 이 화면에서 로그인을 처리한다. 가입 성공 팝업 다음 목적지도 이 화면이다. 앱 최초 진입이 이 화면이라는 문장과, 가입 동의 팝업을 무엇으로 여는지는 명세서에 없다.
- UI: 명세서상 아이디, 비밀번호, eye-off. 피그마에서 추가로 확인한 요소는 브랜드 `약연`, `藥緣 · 약과 사람을 잇다`, `로그인`, `회원가입`, 이용약관·개인정보 처리방침 동의 안내.
- 데이터: 아이디 문자열, 비밀번호 문자열.
- 동작: 로그인 성공 시 SCR-HOME. 실패 시 MDL-LOGIN-ERROR.
- 검증: 실패 조건의 상세(빈 값과 불일치의 구분)는 명세서에 없다. 실패 문구는 `회원정보가 일치하지 않습니다` 하나다.
- 성공: SCR-HOME. 실패: MDL-LOGIN-ERROR.
- 관련 모달: MDL-LOGIN-ERROR. 피그마의 `회원가입` 버튼과 MDL-SIGNUP-GATE의 연결은 명세서에 없다.

### MDL-LOGIN-ERROR 로그인 실패 팝업

- 진입: SCR-LOGIN 실패.
- UI: 명세서 문구 `회원정보가 일치하지 않습니다`. 버튼 구성은 없다. 피그마 프레임 없음.
- 데이터: 없음.
- 동작: 팝업을 만든다고만 되어 있다.
- 검증, 성공, 실패, 이동: 닫은 뒤의 목적지는 명세서에 없다.

### MDL-SIGNUP-GATE 모달 / [팝업] 복약정보 등록 개인정보 수집·이용 동의

- 진입: 명세서 `(완)로그인`의 첫 항목. 어떤 버튼이 이 모달을 여는지는 적혀 있지 않다.
- UI: 명세서상 동의용 체크박스. 피그마 `2280:5176`의 제목은 이용약관 및 동의, 개인정보·민감정보 처리 동의서다. 체크 4개는 [business-rules.md](business-rules.md) 4절. 버튼 `취소`, `동의하고 회원가입 진행`.
- 데이터: 각 체크박스의 체크 여부.
- 동작: 모든 체크가 있어야 회원가입을 진행할 수 있다. 동의하면 SCR-SIGNUP-TYPE.
- 검증: 일부만 체크한 상태에서는 진행할 수 없다. 그때의 별도 오류 문구는 없다.
- 성공: SCR-SIGNUP-TYPE. 실패: 그 화면에 남는다.
- 피그마 `취소`의 목적지는 명세서에 없다.

### SCR-SIGNUP-TYPE 화면 / 회원가입 유형 선택

- 진입: MDL-SIGNUP-GATE에서 동의한 뒤.
- UI: 본인, 대리인. 피그마에는 질문 문구, 두 유형의 설명, `다음`이 있다.
- 데이터: 본인 또는 대리인 하나.
- 동작: 하나만 선택. 미선택 시 관리할 사람을 선택해달라는 문구. 본인이면 바로 SCR-SIGNUP-FORM. 대리인이면 바로 MDL-VIEW-CONSENT.
- 검증: 빈 선택 금지. 동시 선택 금지.
- 성공: 유형에 따라 위 두 목적지. 실패: 선택 요청 문구.
- 피그마의 `다음`과 명세서의 `바로` 이동은 [open-questions.md](open-questions.md) Q-04.

### MDL-VIEW-CONSENT 모달 / 복약자 정보 열람 동의

- 진입: 대리인 선택 직후.
- UI: QR. 명세서 버튼 `먼저 회원가입 진행하기`는 SCR-SIGNUP-FORM으로 간다. 피그마 버튼은 `닫기`, `확인 완료`이고 그 문구의 버튼은 없다.
- 데이터: QR. QR이 어떤 값으로 만들어지는지는 명세서에 없다.
- 동작: 명세서에 적힌 진행 버튼으로 정보 입력에 간다. 복약자의 동의 완료를 기다린다는 문장은 없다.
- 검증: 없음.
- 성공: SCR-SIGNUP-FORM. 피그마 본문은 대리인 가입을 계속하려면 복약자 동의가 필요하다고 시작한다.

### SCR-SIGNUP-FORM 화면 / 회원가입 정보 입력

- 진입: 본인 선택 직후, 또는 대리인 QR 모달의 진행 버튼.
- UI: 이름, 생년월일 달력, 휴대폰, 인증번호 받기, 아이디와 중복 확인, 비밀번호, 비밀번호 확인. 피그마는 2/2 단계와 placeholder를 보여 주며, 생년월일은 `YYYY.MM.DD` 칸으로 보인다. 인증번호 입력 칸과 3분 표시는 프레임에서 확인되지 않았다.
- 데이터: [business-rules.md](business-rules.md) 2절.
- 동작: 인증번호 받기를 누르면 3분 카운트와 입력·확인 칸이 생긴다. 중복 확인은 데이터베이스를 본다. 제출 성공 시 MDL-SIGNUP-SUCCESS 후 SCR-LOGIN.
- 검증: 필수값 누락 시 빠진 항목을 지목. 가입된 번호, 중복 아이디, 비유효 비밀번호는 MDL-SIGNUP-ERROR.
- 성공: MDL-SIGNUP-SUCCESS. 실패: MDL-SIGNUP-ERROR 또는 누락 문구.
- 피그마 placeholder의 자릿수·문자 조합은 명세서 규칙으로 채택되어 있지 않다.

### MDL-SIGNUP-ERROR 가입 오류 팝업

- 진입: 가입된 번호, 중복 아이디, 비유효 비밀번호.
- UI: 팝업. 경우별 문장과 버튼은 명세서에 없다. 피그마에는 주석만 있다.
- 데이터: 어떤 검증이 실패했는지.
- 동작: 팝업을 생성한다.
- 이동: 닫은 뒤의 목적지는 없다.

### MDL-SIGNUP-SUCCESS 가입 성공 팝업

- 진입: 정보 입력 성공.
- UI: 회원가입되었다는 취지의 팝업. 확정 문장과 버튼은 없다.
- 동작: 이 팝업 다음 SCR-LOGIN.
- 실패: 해당 없음.

## 홈과 약물 목록

### SCR-HOME 화면 / 메인 홈

- 진입: 로그인 성공.
- UI: `안녕하세요 [사용자 이름]님`, 복용 중 개수, 아침·점심·저녁 아이콘과 현황 바, 병용금기 건수, 남은 예정만 있는 오늘 복약 리스트. 피그마에 추가로 `약 추가 등록하기`, `이번주 복약 확인하기`, 예시 약물 `아스피린 + 와파린`, 하단 탭이 있다.
- 데이터: 사용자 이름. 복용 중 약물 수. 시간대별 복용 여부. 등재 건수. 오늘 예정 중 남은 항목.
- 동작: 상단 박스 또는 약 추가 등록은 SCR-MED-LIST. 오늘 남은 복약 박스는 SCR-SCHEDULE.
- 검증: 없음.
- 병용금기 영역을 눌렀을 때의 목적지는 명세서에 없다. 피그마에는 MDL-DUR과 SCR-GRAPH가 따로 있다.
- `이번주 복약 확인하기`의 동작은 명세서에 없다.

### SCR-MED-LIST 화면 / 약물 목록·복약 관리

- 진입: 홈의 상단 박스 또는 약 추가 등록. 복용시간 알림의 최종 등록 뒤 추가분을 여기서 확인한다.
- UI: 복용 중 약봉투 수, 복용 중 약 총수, 약 등록 버튼. 복용 중 묶음은 약봉투 이름, 남은 날짜, 약 개수, 약 리스트, 조기 종료. 종료 묶음은 약봉투 이름, 종료 표시, 약 개수, 약 리스트. 피그마 예시는 한의원 D-2, 내과 D-7, 정형외과 종료.
- 데이터: 약봉투와 소속 약, 남은 일수, 종료 여부.
- 동작: 약 등록은 SCR-MED-CONSENT. 조기 종료는 MDL-STOP-MED. 약 칸 길게 누르기는 MDL-MED-CARD.
- 검증: 없음.
- 짧은 누르기의 목적지는 명세서에 없다.

### MDL-STOP-MED 모달 / 복용을 종료하시겠습니까?

- 진입: 복용 조기 종료하기.
- UI: 피그마 설명은 종료 약물을 복용 종료 목록에서 볼 수 있다는 문장. `취소`, `종료`.
- 동작: 명세서가 정한 다음 화면은 없다. 목록 명세는 종료 약물이 아래 구역에 나온다고 정한다.
- `종료`와 `취소` 각각의 목적지는 명세서에 문장으로 없다.

### MDL-MED-CARD 모달 / [팝업]약물 알람 카드

- 진입: 약물 목록의 칸을 길게 누름.
- UI: 수기 수정과 같은 입력 조건. 약물 검색, 복용량 목록, 아침·점심·저녁 복수 선택, 복용 시점 목록, 기간 달력, 삭제, 수정 완료. 피그마는 이 값들을 문자 칸과 칩으로 보여 주고 검색창은 없다.
- 데이터: 해당 약 1개의 이름, 복용량, 횟수, 시점, 기간.
- 동작: 삭제는 MDL-DELETE. 수정 완료는 유효하면 MDL-EDIT-CONFIRM, 잘못되었거나 미입력이면 MDL-TIME-ERROR.
- 검증: 시작일은 약봉지를 받은 날. 약물명은 저장된 약만. 복용량과 시점은 목록 선택. 목록 내용과 `받은 날`의 기준은 미정.
- 성공: MDL-EDIT-CONFIRM. 실패: MDL-TIME-ERROR.

### MDL-EDIT-CONFIRM 모달 / 해당 약물을 수정하시겠습니까?

- 진입: 알람 카드의 수정 완료가 유효할 때.
- UI: 피그마는 제목과 `아니요`, `네`만 확인된다.
- 동작: 명세서에 `네`와 `아니요`의 목적지는 없다.

### MDL-TIME-ERROR 모달 / 복용 시간이 올바르지 않습니다.

- 진입: 명세서상 수정 내용이 올바르지 않거나 전부 입력되지 않았을 때.
- UI: 피그마에서 확인한 문장은 복용 시간을 모두 입력하고 최소 4시간 이상 간격이어야 한다는 내용으로 시작. 버튼 `아니요`, `네`.
- 피그마 주석은 누락 또는 간격이 좁을 때만 이 문구를 출력한다고 한다.
- 버튼 동작은 명세서에 없다.

### MDL-DELETE 모달 / 약물을 삭제하시겠습니까?

- 진입: 알람 카드의 삭제.
- UI: 피그마 설명은 삭제 정보를 다시 불러올 수 없다는 문장. `취소`, `삭제`.
- 동작: 명세서에 확인 후 목록 갱신이라고 적혀 있지는 않다. 설명 문구는 피그마에 있다.

### MDL-DELETE-WIDE 모달 / 약물을 삭제하시겠습니까? · 02

- 진입: 수기 수정의 삭제.
- UI: 같은 제목과 복구 불가 설명. 프레임 폭 360.
- 동작: MDL-DELETE와 버튼 의미의 차이는 명세서에 없다. 진입만 다르다.

## 약물 등록

### SCR-MED-CONSENT 화면 / 복약정보 등록 개인정보 수집·이용 동의

- 진입: 약물 목록의 약 등록하기.
- UI: 동의 본문 스크롤, 체크박스, `동의하고 약 등록`. 피그마 체크는 두 개이며 `취소`가 있다. 본문 항목은 수집 목적, 약 이름·용량·횟수·시간·기간·처방일, 보유 기간, 촬영 원본 파기, 거부권, 촬영 주의, OCR 고지. 전문은 잘려 있다.
- 동작: `동의하고 약 등록`은 SCR-ENVELOPE.
- 검증: 체크를 필수로 막는지 명세서에 없다.
- 피그마 `취소`의 목적지는 명세서에 없다.

### SCR-ENVELOPE 화면 / 약봉지 등록 · 약통 사용 여부

- 진입: 약 등록 동의의 `동의하고 약 등록`.
- UI: 촬영하기, OCR로 채워진 내역, 병원명 문자열, 약물 리스트, 안내 글, 약통 없이 사용하기, 약통에 넣기, 추가 등록. 확인 완료 체크는 명세서가 추가하라고 한 요소이며 피그마 레이어에서는 확인되지 않았다.
- 데이터: 병원명, 인식된 약 목록, 각 약의 확인 여부.
- 동작: 촬영은 OCR 후 자동 완성. 약을 하나씩 눌러 확인. 없는 약은 추가 등록.
- 검증: 모든 약을 확인해야 한다는 문장이 있다. 확인 전에 두 버튼을 막을지는 없다.
- 두 버튼의 이동 문장은 이 화면이 아니라 SCR-ENVELOPE-EDIT에 있다.
- 약을 눌렀을 때의 목적지 화면 이름은 명세서에 없다. 다음 항목이 SCR-ENVELOPE-EDIT이다.

### SCR-ENVELOPE-EDIT 화면 / 수기 수정

- 진입: 명세서가 독립 항목으로 둔다. 약봉투 화면의 항목 누르기와 같은 화면의 펼침인지는 적혀 있지 않다.
- UI: 약물 검색, 복용량 선택, 아침·점심·저녁, 복용 시점 선택, 기간 달력, 삭제. 피그마는 `약 봉투 등록` 제목 아래 약8만 펼쳐져 있고 `삭제` 문구가 있다. 명세서 원문은 삭제가 피그마에서 생략되어 있다고 한다.
- 데이터: [business-rules.md](business-rules.md) 5절.
- 동작: 삭제는 MDL-DELETE-WIDE. 약통 없이 사용하기는 MDL-ALARM-TIME. 약통에 넣기는 SCR-SLOT.
- 검증: 약물명 검색 제한, 복용량·시점 선택 제한, 시작일, 시간대 복수 선택.

### SCR-SLOT 화면 / 약봉지 등록 · 약통 칸 선택

- 진입: `약통에 넣기`.
- UI: 방금 등록한 약 요약, 1·2·3번 칸, 사용 중 표시, 안내 문구, 등록 완료. 피그마는 1·2번 사용 중, 3번 선택, 버튼 `등록 완료`.
- 데이터: 묶음 요약, 칸별 사용 여부, 선택된 칸.
- 동작: 사용 중 칸은 선택할 수 없다. 빈 칸을 고른 뒤 등록 완료는 MDL-ALARM-TIME.
- 검증: 사용 중 칸 선택 금지.
- 빈 칸이 없을 때와 약통 미연결 때는 명세서에 없다.

### MDL-ALARM-TIME 모달 / 피부과 복용시간 알림 설정

- 진입: 약통 없이 사용하기, 또는 칸 선택 후 등록 완료.
- UI: 등록 완료 표시, 아침·점심·저녁 시각, 최종 등록. 피그마는 세 시간대가 모두 있고 `약봉지 1개 등록 완료`를 보여 준다. 제목의 `피부과`는 프레임 이름의 예시이다.
- 데이터: 선택된 시간대와 각 시각.
- 동작: 선택하지 않은 시간대는 출력하지 않는다. 등록 후 SCR-MED-LIST에서 추가분을 확인한다.
- 검증: 시간대 자체의 선택 규칙은 앞 화면의 아침·점심·저녁 체크를 따른다. 한 묶음 안에서 약마다 체크가 다른 경우의 표시 규칙은 없다. 4시간 간격은 이 화면 항목에 없다.

## 복약 일정과 기록

### SCR-SCHEDULE 화면 / 복약 일정

- 진입: 홈의 오늘 남은 복약 박스. MDL-TAKEN에서 안 먹었어요. MDL-TAKEN-TIME의 수동 기록 다음.
- UI: 주간 캘린더, 선택 날짜, 그날의 기록, 완료·누락·예정·지연. 누락이면 복용시간 수정 안내. 피그마에는 `복용 시각 수정`이 누락 행에 있다. 하단 탭 텍스트가 있다.
- 데이터: 날짜, 회차, 상태, 기록 시각.
- 동작: 복용 시간 수정을 누르면 MDL-TAKEN.
- 검증: 없음.

### SCR-SCHEDULE-SAVED 화면 / 복약 일정 · 02

- 진입: 명세서가 별도 기능이 아니라 SCR-SCHEDULE의 수동 기록 결과로 설명한다.
- UI: 피그마는 한 행을 `수동 기록 · 12:10`, 상태 `지연`으로 보여 주고 저장 문구를 낸다.
- 동작: 3시간 이전에는 수동 기록 가능. 이후 자동 누락.
- 저장 직후 상태를 지연으로 둘지 완료로 둘지는 명세서가 정하지 않았다. 피그마 결과는 지연이다.

### MDL-TAKEN 모달 / 피부과 아침 약을 드셨나요?

- 진입: 일정의 복용 시간 수정.
- UI: 안내, `먹었어요`, `안 먹었어요`. 명세서는 체크박스 단일 선택. 피그마에는 `취소`와 감지 실패 안내가 있다.
- 동작: 먹었어요는 MDL-ROUND. 안 먹었어요는 SCR-SCHEDULE.
- 검증: 둘 중 하나만.

### MDL-ROUND 모달 / 어느 회차 약을 드셨나요?

- 진입: 먹었어요.
- UI: 복용 시간대 단일 선택. 피그마 예시는 이전 회차와 현재 회차, `취소`.
- 동작: 이전 회차는 그 알림 시각에서 3시간이 지나면 선택할 수 없다.
- 선택 후 MDL-TAKEN-TIME으로 간다는 문장은 명세서에 없다.

### MDL-TAKEN-TIME 모달 / 몇시에 드셨나요?

- 진입: 명세서가 다음 번호로 두었으나, 이전 모달이 이 모달을 연다고 적지는 않았다.
- UI: 안내, 시간 기록, `수동으로 기록하기`. 피그마는 오늘만 수정 가능하고 지난 날짜는 읽기 전용이라고 시작한다. `취소`가 있다.
- 동작: 시각 입력 후 수동 기록하면 SCR-SCHEDULE로 돌아가며 저장되었다고 안내한다. 결과 모습은 SCR-SCHEDULE-SAVED.
- 검증: 지난 날짜 읽기 전용은 피그마 문구이며 명세서 조건이 아니다. 3시간 제한은 일정 `· 02` 설명과 회차 선택에 있다.

### SCR-HISTORY 화면 / 복용 알림

- 진입: 어떤 화면에서든 comment-alt 아이콘. 아이콘의 위치는 피그마 프레임 목록에서 확인하지 못했다.
- UI: 전체·정상·지연·누락, 기간 설정, 오늘·어제·3일 전 이후 날짜 섹션, 현재 시각 기준 복용 여부. 피그마 제목은 `복용 내역`이고 예시 기간은 최근 2주다.
- 데이터: 일정의 일일 기록을 단순화한 이력. 최대 1년.
- 동작: 필터와 기간 설정. 그 외 행을 눌렀을 때의 목적지는 없다.
- 원문은 이 이력을 `복용 일정` 탭의 일일 내역이라고 부른다. 프레임 이름은 `복약 일정`이다.

- 동작: 바로가기는 복용자 권한 관리용 웹을 연다.
